# Java 工程化能力合集

## 这份文档是什么

这是一套围绕 Java 后端工程化能力整理出来的知识文档合集。  
它不是单纯的框架 API 笔记，也不是零散的面试题汇总，而是尽量按照真实项目的视角，把一个完整后端系统常见的能力拆成多个大类，再在每个大类下继续拆分经典功能点。

这套文档更关注下面这些问题：

- 一个功能在项目里为什么需要这样设计
- 它在真实系统里通常长什么样
- 实现时有哪些核心链路
- 常见坑点在哪里
- 和其他模块之间怎么衔接

所以你可以把它理解成：

- 一份 Java 后端工程化能力地图
- 一套可持续扩展的系统设计学习手册

## 适合谁看

这套文档特别适合下面几类人：

1. 已经会一些 Java 后端技术，但缺少系统设计感和工程化视角的人
2. 想从“会框架”走向“会做完整项目”的人
3. 想整理一套长期可复用的后端知识库的人
4. 想从功能实现角度复盘主流后端能力的人

## 这套合集的组织方式

整套内容按 12 个大类组织，每个大类下面再拆成多个具体能力点。  
每个大类目录下都已经补了一份自己的 `README.md`，里面会继续说明：

- 本类定位
- 适用场景
- 文档导航
- 推荐阅读顺序
- 与其他大类的关联

所以你可以：

1. 从这个总首页先看全局地图
2. 再点进某个大类的 `README.md`
3. 再顺着该类里的具体文章继续学习

## 这套合集最适合怎么用

我更推荐下面这几种使用方式：

### 方式一：按目录系统学习

适合：

- 想从头系统梳理工程化能力的人

做法：

1. 先看总 README
2. 再看某个大类 README
3. 再按推荐顺序读具体文章

### 方式二：按项目问题反查

适合：

- 正在做项目，遇到某个具体问题的人

做法：

- 遇到支付问题，就进业务流程类
- 遇到缓存问题，就进高并发与稳定性类
- 遇到日志告警问题，就进运维与治理类

### 方式三：按系统设计复盘

适合：

- 想把做过的项目重新拆解成模块能力的人

做法：

- 对照 12 大类，把你项目里已有的能力一项项映射过去
- 看哪些你已经做过，哪些还停留在概念层
