# 工作流实现

## 1. 功能定义

工作流要解决的问题是：

- 一个复杂业务从开始到结束，如何按照预定义的节点、条件和处理人规则自动推进

和审批流相比，工作流更强调“整个业务过程的编排”，而不只是审批动作本身。

例如一个采购流程，可能不仅包含：

- 发起申请
- 多级审批

还包含：

- 采购下单
- 入库确认
- 财务结算

这就已经超出了单纯审批流的范围，进入了工作流领域。

## 2. 工作流和审批流的关系

可以先用一个比较实用的理解：

- 审批流是工作流的一种常见子流程
- 工作流比审批流更广，节点类型更多

工作流节点可以是：

- 用户任务节点
- 审批节点
- 条件分支节点
- 抄送节点
- 系统自动执行节点
- 结束节点

## 3. 一个工作流通常包含什么

从工程建模上看，最常见的工作流通常会拆成：

1. 流程定义
2. 流程节点定义
3. 流程实例
4. 流程任务实例

流程定义描述的是“应该怎么走”，流程实例描述的是“某一次具体怎么走到了哪”。

## 4. 典型流程

以一个简单工作流为例：

1. 发起申请
2. 部门经理审批
3. 金额大于 10000 则进入总监审批，否则跳过
4. 财务确认
5. 流程结束

这类流程的关键点在于：

- 不同节点之间可能有条件分支
- 不是每次都走完全一样的路径

## 5. 核心设计

工作流设计时，我建议先抓住这几个核心：

1. 定义和实例分离
2. 节点推进是核心能力
3. 条件路由要可配置
4. 运行时一定要有当前任务概念
5. 状态流转和操作日志必须完整

## 7. 核心代码

## 7.1 启动流程实例

```java
@Service
public class WorkflowServiceImpl implements WorkflowService {

    private final ProcessDefinitionMapper processDefinitionMapper;
    private final ProcessNodeDefinitionMapper processNodeDefinitionMapper;
    private final ProcessInstanceMapper processInstanceMapper;
    private final ProcessTaskMapper processTaskMapper;

    public WorkflowServiceImpl(
            ProcessDefinitionMapper processDefinitionMapper,
            ProcessNodeDefinitionMapper processNodeDefinitionMapper,
            ProcessInstanceMapper processInstanceMapper,
            ProcessTaskMapper processTaskMapper) {
        this.processDefinitionMapper = processDefinitionMapper;
        this.processNodeDefinitionMapper = processNodeDefinitionMapper;
        this.processInstanceMapper = processInstanceMapper;
        this.processTaskMapper = processTaskMapper;
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void start(String processCode, Long bizId, Long starterUserId) {
        ProcessDefinition definition = processDefinitionMapper.selectByCode(processCode);
        if (definition == null) {
            throw new BizException("流程定义不存在");
        }

        ProcessNodeDefinition firstNode = processNodeDefinitionMapper.selectFirstNode(definition.getId());
        if (firstNode == null) {
            throw new BizException("流程未配置开始节点");
        }

        ProcessInstance instance = new ProcessInstance();
        instance.setProcessCode(processCode);
        instance.setBizId(bizId);
        instance.setStarterUserId(starterUserId);
        instance.setStatus("RUNNING");
        instance.setCurrentNodeCode(firstNode.getNodeCode());
        instance.setCreateTime(LocalDateTime.now());
        processInstanceMapper.insert(instance);

        ProcessTask task = new ProcessTask();
        task.setInstanceId(instance.getId());
        task.setNodeCode(firstNode.getNodeCode());
        task.setNodeName(firstNode.getNodeName());
        task.setStatus("WAIT_HANDLE");
        task.setHandlerUserId(resolveHandler(firstNode, starterUserId));
        processTaskMapper.insert(task);
    }

    private Long resolveHandler(ProcessNodeDefinition node, Long starterUserId) {
        return starterUserId;
    }
}
```

## 7.2 推进工作流节点

```java
@Override
@Transactional(rollbackFor = Exception.class)
public void completeTask(Long taskId, Long handlerUserId, String action) {
    ProcessTask task = processTaskMapper.selectById(taskId);
    if (task == null) {
        throw new BizException("任务不存在");
    }
    if (!"WAIT_HANDLE".equals(task.getStatus())) {
        throw new BizException("任务已处理");
    }
    if (!Objects.equals(task.getHandlerUserId(), handlerUserId)) {
        throw new BizException("当前用户无权处理该任务");
    }

    ProcessTask taskUpdate = new ProcessTask();
    taskUpdate.setId(taskId);
    taskUpdate.setStatus("DONE");
    taskUpdate.setAction(action);
    taskUpdate.setHandleTime(LocalDateTime.now());
    processTaskMapper.updateById(taskUpdate);

    ProcessInstance instance = processInstanceMapper.selectById(task.getInstanceId());
    ProcessNodeDefinition currentNode = processNodeDefinitionMapper.selectByNodeCode(
            instance.getProcessCode(),
            task.getNodeCode()
    );

    ProcessNodeDefinition nextNode = processNodeDefinitionMapper.selectByNodeCode(
            instance.getProcessCode(),
            currentNode.getNextNodeCode()
    );

    if (nextNode == null) {
        ProcessInstance finishUpdate = new ProcessInstance();
        finishUpdate.setId(instance.getId());
        finishUpdate.setStatus("FINISHED");
        finishUpdate.setCurrentNodeCode(null);
        processInstanceMapper.updateById(finishUpdate);
        return;
    }

    ProcessInstance runningUpdate = new ProcessInstance();
    runningUpdate.setId(instance.getId());
    runningUpdate.setCurrentNodeCode(nextNode.getNodeCode());
    processInstanceMapper.updateById(runningUpdate);

    ProcessTask nextTask = new ProcessTask();
    nextTask.setInstanceId(instance.getId());
    nextTask.setNodeCode(nextNode.getNodeCode());
    nextTask.setNodeName(nextNode.getNodeName());
    nextTask.setStatus("WAIT_HANDLE");
    nextTask.setHandlerUserId(resolveHandler(nextNode, instance.getStarterUserId()));
    processTaskMapper.insert(nextTask);
}
```

这段代码是工作流实现里的核心骨架。  
本质上它做的是：

1. 关闭当前任务
2. 找到下一个节点
3. 更新流程实例当前位置
4. 创建下一条待处理任务

## 8. 条件分支怎么理解

工作流和简单审批流最大的不同之一，就是它常常有条件路由。  
例如：

- 金额小于 1000，直接财务确认
- 金额大于等于 1000，需要总监审批

这时候“下一个节点”就不再是固定字段，而是基于条件计算出来。

所以更完整的工作流实现里，通常还会有：

- 条件表达式
- 路由规则
- 节点分支定义

## 9. 为什么工作流一定要有任务实例

因为流程实例只告诉你：

- 这个流程现在跑到哪里了

但真正驱动人去处理的，通常是任务实例。  
任务实例关心的是：

- 这一刻谁需要处理什么

没有任务实例，很多待办列表、已办列表、催办能力都会很难做。

## 10. 常见坑点

### 10.1 流程定义和运行实例混在一起

后续版本演进会非常麻烦。

### 10.2 只有流程状态，没有任务状态

前端很难做待办、已办、处理中列表。

### 10.3 节点推进不校验当前状态

容易出现重复处理。

## 11. 总结

工作流的核心，不是“画一张流程图”，而是把流程定义、实例推进、任务生成和条件路由真正落到代码和数据结构中。

一个成熟的工作流实现至少应该做到：

- 定义和实例分离
- 当前任务明确
- 节点推进有状态校验
- 路由规则可扩展

这样后面才能逐步演进出更复杂的业务流程平台。
