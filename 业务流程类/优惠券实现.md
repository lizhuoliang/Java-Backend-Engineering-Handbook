# 优惠券实现

## 1. 功能定义

优惠券要解决的问题是：

- 系统如何用一张可发放、可领取、可核销的优惠凭证，影响订单最终应付金额

它看起来只是“减一点钱”，但真实业务里通常会涉及：

- 优惠券发放
- 用户领取
- 使用门槛校验
- 优惠金额计算
- 核销和回退

所以优惠券本质上不是一个简单字段，而是一套完整的营销与订单协同能力。

## 2. 优惠券通常包含哪些信息

一个优惠券最基础的信息通常有：

```json
{
  "couponId": 88,
  "couponName": "满200减30",
  "type": "FULL_REDUCTION",
  "thresholdAmount": 200.00,
  "discountAmount": 30.00,
  "status": "ENABLED",
  "validStartTime": "2026-06-01 00:00:00",
  "validEndTime": "2026-06-30 23:59:59"
}
```

如果优惠券下发到用户，还会有一层“用户优惠券”关系，例如：

```json
{
  "userCouponId": 10001,
  "userId": 101,
  "couponId": 88,
  "status": "UNUSED"
}
```

这里最重要的一点是：

- 优惠券定义
- 用户持有的券

通常要分开。

## 3. 常见优惠券类型

工程里常见的券类型包括：

1. 满减券
2. 直减券
3. 折扣券
4. 运费券

这几种券的计算方式不同，所以真正的优惠券系统通常要先抽出“计算规则”。

## 4. 典型流程

一个典型的优惠券流程通常如下：

1. 系统发券或用户领券
2. 下单时用户选择某张券
3. 系统校验券是否可用
4. 计算优惠金额
5. 订单支付成功后核销优惠券
6. 如果订单取消或退款，按规则决定是否回退优惠券

## 5. 核心设计

优惠券实现时，我建议先明确：

1. 券定义和用户券分离
2. 是否可用一定以后端校验为准
3. 券状态流转要清晰
4. 券计算规则要可扩展
5. 核销动作必须幂等

## 6. 核心代码

## 6.1 下单前优惠计算核心实现

```java
@Service
public class CouponServiceImpl implements CouponService {

    private final CouponMapper couponMapper;
    private final UserCouponMapper userCouponMapper;

    public CouponServiceImpl(
            CouponMapper couponMapper,
            UserCouponMapper userCouponMapper) {
        this.couponMapper = couponMapper;
        this.userCouponMapper = userCouponMapper;
    }

    @Override
    public BigDecimal calculateDiscount(Long userCouponId, Long userId, BigDecimal totalAmount) {
        if (userCouponId == null) {
            return BigDecimal.ZERO;
        }

        UserCoupon userCoupon = userCouponMapper.selectById(userCouponId);
        if (userCoupon == null || !Objects.equals(userCoupon.getUserId(), userId)) {
            throw new BizException("优惠券不存在");
        }
        if (!"UNUSED".equals(userCoupon.getStatus())) {
            throw new BizException("优惠券不可用");
        }

        Coupon coupon = couponMapper.selectById(userCoupon.getCouponId());
        if (coupon == null || !"ENABLED".equals(coupon.getStatus())) {
            throw new BizException("优惠券已失效");
        }

        LocalDateTime now = LocalDateTime.now();
        if (now.isBefore(coupon.getValidStartTime()) || now.isAfter(coupon.getValidEndTime())) {
            throw new BizException("优惠券不在有效期内");
        }

        if ("FULL_REDUCTION".equals(coupon.getType())) {
            if (totalAmount.compareTo(coupon.getThresholdAmount()) < 0) {
                throw new BizException("未达到优惠券使用门槛");
            }
            return coupon.getDiscountAmount();
        }

        if ("DIRECT_REDUCTION".equals(coupon.getType())) {
            return coupon.getDiscountAmount();
        }

        return BigDecimal.ZERO;
    }
}
```

这段代码的关键点有：

- 优惠券属于当前用户
- 优惠券必须处于未使用状态
- 优惠券定义必须有效
- 优惠金额根据规则计算

## 6.2 支付成功后核销优惠券

```java
@Override
@Transactional(rollbackFor = Exception.class)
public void consumeCoupon(Long userCouponId, Long orderId) {
    if (userCouponId == null) {
        return;
    }

    UserCoupon userCoupon = userCouponMapper.selectById(userCouponId);
    if (userCoupon == null) {
        throw new BizException("优惠券不存在");
    }
    if ("USED".equals(userCoupon.getStatus())) {
        return;
    }

    UserCoupon update = new UserCoupon();
    update.setId(userCouponId);
    update.setStatus("USED");
    update.setUseOrderId(orderId);
    update.setUseTime(LocalDateTime.now());
    userCouponMapper.updateById(update);
}
```

核销动作做幂等非常重要，因为支付成功回调本身就可能重复触发。

## 7. 为什么优惠券不能在下单时立刻置为已使用

因为下单不代表支付成功。  
如果用户：

- 下单后没支付
- 下单后取消订单

这张券如果已经被直接置为已使用，就会产生错误占用。

更稳的做法通常是：

1. 下单时只做可用性校验
2. 支付成功后再正式核销

如果项目更复杂，也可以做：

- 下单暂锁券
- 超时自动释放

## 8. 券回退怎么理解

当订单取消、支付失败或退款成功时，优惠券是否回退，要看业务规则。  
常见规则有两种：

1. 未支付取消，直接恢复未使用
2. 已支付后退款，是否退券按平台规则决定

所以优惠券系统和订单逆向流程一定是有联动关系的。

## 9. 常见坑点

### 9.1 前端自己计算优惠金额

后端必须重新算，不能信任前端。

### 9.2 下单即核销优惠券

很容易造成券被错误占用。

### 9.3 不做有效期和状态校验

会导致过期券、已用券被重复使用。

## 10. 总结

优惠券实现的核心，不是“减多少钱”，而是围绕券定义、用户持券、使用校验、金额计算和核销回退，建立一套和订单系统协同的优惠机制。

一个成熟的实现至少应该做到：

- 券定义与用户券分离
- 使用资格以后端校验为准
- 金额后端计算
- 核销动作支付成功后执行

这才是能真正落地的优惠券系统基础。
