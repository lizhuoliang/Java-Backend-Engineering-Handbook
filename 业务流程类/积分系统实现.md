# 积分系统实现

## 1. 功能定义

积分系统要解决的问题是：

- 用户在完成某些行为后，系统如何发放、扣减和追踪积分

常见场景包括：

- 注册送积分
- 支付送积分
- 签到送积分
- 退款扣回积分
- 积分兑换商品

积分系统看起来只是一个分数字段，但如果没有账务思维，很快就会失控。  
因为真正重要的不只是“用户现在有多少积分”，而是：

- 这些积分是怎么来的
- 什么时候扣的
- 为什么变成这个值

## 2. 积分系统为什么要有流水

和余额系统类似，积分系统最重要的不是总值，而是流水。  
通常至少会有：

1. 用户积分账户
2. 积分流水表

例如：

```json
{
  "account": {
    "userId": 101,
    "totalPoint": 500
  },
  "log": {
    "bizType": "ORDER_PAY",
    "bizId": 90001,
    "changeType": "ADD",
    "point": 50
  }
}
```

没有流水，就几乎无法解释积分变化过程。

## 3. 典型流程

一个比较典型的积分发放流程如下：

1. 用户完成某个行为
2. 系统判断该行为是否应该给积分
3. 计算积分数
4. 增加账户积分
5. 记录积分流水

如果是积分消费，则反过来：

1. 校验积分余额
2. 扣减账户积分
3. 记录扣减流水

## 4. 核心设计

积分系统实现时，建议重点考虑：

1. 账户和流水分离
2. 发放和扣减都要留痕
3. 相同行为要防止重复发积分
4. 退款等逆向业务要支持积分回退

## 5. 核心代码

## 5.1 支付成功发积分核心实现

```java
@Service
public class PointServiceImpl implements PointService {

    private final UserPointAccountMapper userPointAccountMapper;
    private final UserPointLogMapper userPointLogMapper;

    public PointServiceImpl(
            UserPointAccountMapper userPointAccountMapper,
            UserPointLogMapper userPointLogMapper) {
        this.userPointAccountMapper = userPointAccountMapper;
        this.userPointLogMapper = userPointLogMapper;
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void addOrderPayPoint(Long userId, Long orderId, Integer point) {
        boolean exists = userPointLogMapper.existsByBiz("ORDER_PAY", orderId, "ADD");
        if (exists) {
            return;
        }

        int updated = userPointAccountMapper.addPoint(userId, point);
        if (updated == 0) {
            throw new BizException("积分账户不存在");
        }

        UserPointLog log = new UserPointLog();
        log.setUserId(userId);
        log.setBizType("ORDER_PAY");
        log.setBizId(orderId);
        log.setChangeType("ADD");
        log.setPoint(point);
        log.setCreateTime(LocalDateTime.now());
        userPointLogMapper.insert(log);
    }
}
```

这段代码最重要的不是“加了积分”，而是：

- 先做幂等判断
- 再改账户
- 再留流水

## 5.2 退款扣回积分核心实现

```java
@Override
@Transactional(rollbackFor = Exception.class)
public void rollbackOrderPayPoint(Long userId, Long orderId, Integer point) {
    boolean exists = userPointLogMapper.existsByBiz("ORDER_REFUND", orderId, "SUB");
    if (exists) {
        return;
    }

    int updated = userPointAccountMapper.subPoint(userId, point);
    if (updated == 0) {
        throw new BizException("积分不足或账户不存在");
    }

    UserPointLog log = new UserPointLog();
    log.setUserId(userId);
    log.setBizType("ORDER_REFUND");
    log.setBizId(orderId);
    log.setChangeType("SUB");
    log.setPoint(point);
    log.setCreateTime(LocalDateTime.now());
    userPointLogMapper.insert(log);
}
```

## 6. 为什么积分系统一定要幂等

因为很多积分动作都和业务事件绑定，例如：

- 支付成功发积分
- 退款扣回积分

而这些事件本身可能重复触发。  
如果不做幂等，就可能出现：

- 同一笔订单被重复发积分
- 同一笔退款被重复扣积分

所以工程上几乎一定会用：

- `bizType + bizId + changeType`

来作为积分流水幂等判断依据。

## 7. 积分过期怎么理解

有些系统里的积分不是永久有效，而是：

- 一年有效
- 活动积分 30 天有效

这时积分系统就会更复杂，因为除了总账户外，还可能要追踪：

- 每一笔积分的有效期
- 哪一批积分先消费

如果当前只是搭骨架，可以先不做复杂过期模型，但要知道这是积分系统常见扩展方向。

## 8. 常见坑点

### 8.1 只在用户表上存一个积分字段

后续很难审计和追踪。

### 8.2 发积分不做幂等

重复回调时会直接多发。

### 8.3 退款时不回退积分

会导致正逆向业务不一致。

## 9. 总结

积分系统的核心，不是“有个积分数字”，而是围绕积分账户、积分流水和业务幂等，建立一套可追踪、可回退、可审计的积分账务体系。

只要把账户、流水、幂等这三层打稳，后面做积分商城、积分过期、积分兑换都会顺很多。
