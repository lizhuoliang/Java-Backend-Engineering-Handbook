# 业务流程类

## 本类定位

这一类主要解决系统中的“核心业务链路怎么流转”，也就是：

- 一个业务对象从创建、推进、变更到结束，系统如何按规则组织和治理

如果说前几类更多是在搭基础能力，那么这一类更像是在回答：

- 一个真实业务系统到底怎么运转起来

这里也是最接近“系统设计感”的一类内容。

## 适用场景

- 电商订单流转
- 审批与工作流系统
- 库存与逆向流程
- 营销优惠与积分体系
- 结算与对账

## 推荐阅读顺序

推荐顺序如下：

1. 状态流转
2. 订单创建
3. 库存扣减
4. 订单支付
5. 订单取消
6. 库存回滚
7. 订单退款
8. 优惠券
9. 活动系统
10. 积分系统
11. 审批流
12. 工作流
13. 任务分配
14. 结算
15. 对账

理解顺序可以概括为：

- 先理解流程状态怎么被约束
- 再理解订单和库存这一条主链路
- 再理解营销、审批、结算这些复杂扩展链路

## 与其他大类的关联

- 和 [高并发与稳定性类](../高并发与稳定性类/README.md) 的关系
库存扣减、支付回调、异步削峰、幂等和热点治理都直接影响业务流程稳定性。

- 和 [消息与通知类](../消息与通知类/README.md) 的关系
订单、审批、退款、结算等都会触发通知体系。

- 和 [数据分析类](../数据分析类/README.md) 的关系
业务流程的每个关键状态变化，都会沉淀成后续统计、看板、对账和归档的数据基础。
