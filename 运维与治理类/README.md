# 运维与治理类

## 本类定位

这一类主要解决系统上线之后“怎么被观察、怎么被发现异常、怎么被配置、怎么被发布和治理”的问题。

它的核心不是新增业务功能，而是让系统从：

- 能跑

进一步走向：

- 可运维
- 可发布
- 可诊断
- 可治理

## 适用场景

- 日志和监控体系搭建
- 故障排查和告警治理
- 微服务运行与发布治理
- 配置动态管理
- 健康状态和接口说明治理

## 推荐阅读顺序

推荐顺序如下：

1. 日志采集
2. 监控
3. 告警
4. 链路追踪
5. 健康检查
6. 配置管理
7. 服务注册发现
8. 灰度发布
9. 接口文档管理

理解顺序可以概括为：

- 先让系统可见
- 再让系统可预警
- 再让系统可发布、可治理、可协作

## 与其他大类的关联

- 和 [高并发与稳定性类](../高并发与稳定性类/README.md) 的关系
缓存、熔断、降级、限流等机制最终都要靠监控和日志验证效果。

- 和 [任务与调度类](../任务与调度类/README.md) 的关系
定时任务、批处理、补偿任务都需要日志、监控和告警托底。

- 和 [开放平台与集成类](../开放平台与集成类/README.md) 的关系
外部对接、Webhook、开放平台都依赖日志、链路和健康检查做治理。
