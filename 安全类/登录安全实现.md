# 登录安全实现

## 1. 功能定义

登录安全要解决的问题是：

- 系统如何在允许合法用户登录的同时，尽量阻止账号被撞库、被盗用、被暴力破解或被会话劫持

很多人第一次做登录，只关注：

- 用户名密码对不对
- 登录成功后发 token

但在真实系统里，登录恰恰是最容易被攻击的入口之一。  
因为它天然暴露了：

- 账号身份入口
- 密码校验入口
- 会话生成入口

所以登录安全不是“登录功能的附属项”，而是认证体系里最核心的一层安全防线。

## 2. 登录安全通常要防什么

最常见的风险包括：

1. 暴力破解  
同一账号被反复试密码。

2. 撞库登录  
攻击者拿到别处泄露的账号密码批量尝试登录。

3. 会话盗用  
token 或 session 被窃取后冒用。

4. 弱口令问题  
用户密码本身过于简单。

5. 异常设备登录  
异地、异设备、异常 IP 登录。

所以一个成熟的登录安全体系，通常不是一条校验逻辑，而是多层组合保护。

## 3. 登录安全的核心分层

从工程角度看，登录安全一般会分成四层：

1. 账号口令安全  
密码加密、密码强度、错误次数控制。

2. 登录行为安全  
验证码、限流、防刷、设备/IP 风险控制。

3. 会话安全  
token 生命周期、续期、退出失效、单端/多端控制。

4. 审计与告警  
记录登录日志、异常登录告警。

## 4. 一个更完整的安全登录流程

一个工程化的登录安全流程通常如下：

1. 前端提交用户名和密码
2. 后端校验基础参数
3. 校验当前账号/IP/设备是否被限制
4. 查询用户信息
5. 校验密码
6. 判断账号状态
7. 记录本次登录结果
8. 如果失败次数过多，触发验证码或临时锁定
9. 如果成功，则签发 token 并建立登录态
10. 返回登录成功结果

## 5. 核心设计

登录安全实现时，建议至少考虑：

1. 密码必须安全存储
2. 登录失败次数必须受控
3. token 必须可失效、可过期
4. 登录行为必须留痕
5. 异常登录最好可识别

## 6. 核心代码

## 6.1 登录失败次数限制

最基础的一层保护通常是：

- 连续失败达到阈值后，暂时拒绝登录或要求验证码

```java
@Service
public class LoginSecurityServiceImpl implements LoginSecurityService {

    private static final String LOGIN_FAIL_KEY = "login:fail:";

    private final StringRedisTemplate stringRedisTemplate;

    public LoginSecurityServiceImpl(StringRedisTemplate stringRedisTemplate) {
        this.stringRedisTemplate = stringRedisTemplate;
    }

    @Override
    public void checkLoginAllowed(String username) {
        String countStr = stringRedisTemplate.opsForValue().get(LOGIN_FAIL_KEY + username);
        if (countStr == null) {
            return;
        }

        int failCount = Integer.parseInt(countStr);
        if (failCount >= 5) {
            throw new BizException("登录失败次数过多，请稍后再试");
        }
    }

    @Override
    public void recordLoginFail(String username) {
        String key = LOGIN_FAIL_KEY + username;
        Long count = stringRedisTemplate.opsForValue().increment(key);
        if (count != null && count == 1L) {
            stringRedisTemplate.expire(key, Duration.ofMinutes(15));
        }
    }

    @Override
    public void clearLoginFail(String username) {
        stringRedisTemplate.delete(LOGIN_FAIL_KEY + username);
    }
}
```

这段代码展示的是登录安全里最基础但很有效的一层：

- 连续失败控制

## 6.2 登录主流程中的安全接入

```java
@Service
public class AuthServiceImpl implements AuthService {

    private final UserMapper userMapper;
    private final PasswordEncoder passwordEncoder;
    private final LoginSecurityService loginSecurityService;
    private final LoginLogService loginLogService;

    public AuthServiceImpl(
            UserMapper userMapper,
            PasswordEncoder passwordEncoder,
            LoginSecurityService loginSecurityService,
            LoginLogService loginLogService) {
        this.userMapper = userMapper;
        this.passwordEncoder = passwordEncoder;
        this.loginSecurityService = loginSecurityService;
        this.loginLogService = loginLogService;
    }

    @Override
    public void login(LoginRequest request, String clientIp) {
        loginSecurityService.checkLoginAllowed(request.getUsername());

        User user = userMapper.selectByUsername(request.getUsername());
        if (user == null) {
            loginSecurityService.recordLoginFail(request.getUsername());
            loginLogService.record(request.getUsername(), clientIp, "FAIL", "用户不存在");
            throw new BizException("用户名或密码错误");
        }

        if (!passwordEncoder.matches(request.getPassword(), user.getPassword())) {
            loginSecurityService.recordLoginFail(request.getUsername());
            loginLogService.record(request.getUsername(), clientIp, "FAIL", "密码错误");
            throw new BizException("用户名或密码错误");
        }

        if (!"ENABLE".equals(user.getStatus())) {
            loginLogService.record(request.getUsername(), clientIp, "FAIL", "账号禁用");
            throw new BizException("账号已被禁用");
        }

        loginSecurityService.clearLoginFail(request.getUsername());
        loginLogService.record(request.getUsername(), clientIp, "SUCCESS", null);

        // 继续签发 token、建立登录态
    }
}
```

这段代码里最重要的并不是“登录成功”，而是：

- 失败也被记录
- 失败也会积累风险状态

## 7. 为什么密码安全不只是“加密存储”

很多人一提登录安全，就只想到：

- 密码别明文存库

这当然非常重要，但还不够。  
密码安全通常至少包括：

1. 使用 `BCrypt` 等安全哈希算法
2. 要求基本密码强度
3. 修改密码后让旧会话失效
4. 避免在日志中输出原始密码

所以密码加密只是起点，不是全部。

## 8. 登录日志为什么重要

登录日志是登录安全体系中非常关键的一层。  
它至少能帮助回答：

- 某个账号今天被尝试登录了多少次
- 哪些登录来自异常 IP
- 哪次登录失败、为什么失败
- 用户是否在异地异常登录

没有登录日志，很多安全事件只能靠猜。

## 9. 登录安全的进一步增强

如果系统安全要求更高，通常还会继续增加：

1. 图形验证码
2. 二次验证  
例如短信验证码、邮箱验证码、OTP。

3. 设备指纹识别
4. 异地登录提醒
5. 单端登录控制

也就是说，密码登录只是认证入口，真正的登录安全体系通常会逐步走向：

- 风险识别 + 分级验证

## 10. 常见坑点

### 10.1 只校验密码，不限制失败次数

非常容易被暴力破解或撞库。

### 10.2 登录失败不记录日志

后续很难做风险分析。

### 10.3 token 永不过期

一旦泄露，会话风险会非常大。

### 10.4 用户名不存在和密码错误返回不同提示

会帮助攻击者枚举账号。

## 11. 总结

登录安全的核心，不是“登录接口能跑通”，而是围绕账号口令、登录行为、会话安全和日志审计，建立一套可防撞库、可控风险、可追踪异常的认证入口保护体系。

一个成熟的登录安全实现至少应该做到：

- 密码安全存储
- 连续失败限制
- 登录行为留痕
- token 可失效可过期
- 异常行为可扩展识别

这才是真正接近生产环境的登录安全能力。
