# 外部系统同步实现

## 1. 功能定义

外部系统同步要解决的问题是：

- 你的系统和别的系统之间，如何交换数据并保持关键状态尽量一致

这在企业系统里非常常见。  
例如：

- ERP 同步商品数据到商城
- OA 同步组织架构到业务系统
- CRM 同步客户数据到客服系统
- 外部合作方同步订单或库存

所以“系统集成”很多时候并不是一次性导入，而是长期的数据同步问题。

## 2. 同步最难的地方不在接口调用

很多人一开始会把“系统同步”理解成：

- 调一下对方接口

但真实难点往往在于：

1. 谁是主数据源
2. 全量同步还是增量同步
3. 数据不一致时谁覆盖谁
4. 失败重试怎么做
5. 同步延迟是否可接受

也就是说，外部系统同步的本质不是“能调通接口”，而是：

- 数据一致性策略设计

## 3. 常见同步模式

最常见的同步方式包括：

1. 定时拉取  
你的系统定时去对方拉数据。

2. 对方推送  
对方通过 Webhook 或 MQ 把变更推给你。

3. 双向同步  
双方都能推也都能拉，但复杂度最高。

4. 文件交换  
例如定时导入导出 CSV / Excel / 批量文件。

在大多数企业系统里，最常见的是：

- 定时增量同步
- Webhook 推送同步

## 4. 核心设计

外部系统同步实现时，建议重点考虑：

1. 主数据归属是谁
2. 同步粒度是全量还是增量
3. 同步幂等怎么做
4. 同步失败怎么补偿
5. 同步日志和结果如何留痕

这里最关键的一点是：

- 不要一上来就追求“双向实时强一致”

大多数系统集成场景下，这既难又不现实。  
更合理的目标通常是：

- 明确主从关系
- 保证最终一致

## 5. 典型流程

以“从 ERP 同步商品到商城”为例，一个常见流程如下：

1. 定时任务触发同步
2. 按上次同步时间拉取增量商品
3. 逐条映射为本地商品模型
4. 根据外部商品 ID 做幂等更新
5. 记录同步成功和失败结果
6. 更新本次同步点位

## 6. 核心代码

## 6.1 增量同步核心实现

```java
@Service
public class ProductSyncServiceImpl implements ProductSyncService {

    private final ErpClient erpClient;
    private final ProductMapper productMapper;
    private final SyncTaskLogMapper syncTaskLogMapper;

    public ProductSyncServiceImpl(
            ErpClient erpClient,
            ProductMapper productMapper,
            SyncTaskLogMapper syncTaskLogMapper) {
        this.erpClient = erpClient;
        this.productMapper = productMapper;
        this.syncTaskLogMapper = syncTaskLogMapper;
    }

    @Override
    public void sync(LocalDateTime lastSyncTime) {
        List<ErpProductDTO> products = erpClient.queryUpdatedProducts(lastSyncTime);
        for (ErpProductDTO dto : products) {
            try {
                Product exist = productMapper.selectByExternalId(dto.getExternalId());

                Product product = new Product();
                product.setExternalId(dto.getExternalId());
                product.setName(dto.getName());
                product.setPrice(dto.getPrice());
                product.setStatus(dto.getStatus());

                if (exist == null) {
                    productMapper.insert(product);
                } else {
                    product.setId(exist.getId());
                    productMapper.updateById(product);
                }

                saveSyncLog("PRODUCT", dto.getExternalId(), "SUCCESS", null);
            } catch (Exception ex) {
                saveSyncLog("PRODUCT", dto.getExternalId(), "FAIL", ex.getMessage());
            }
        }
    }

    private void saveSyncLog(String bizType, String externalId, String status, String failReason) {
        SyncTaskLog log = new SyncTaskLog();
        log.setBizType(bizType);
        log.setExternalId(externalId);
        log.setStatus(status);
        log.setFailReason(failReason);
        log.setCreateTime(LocalDateTime.now());
        syncTaskLogMapper.insert(log);
    }
}
```

这段代码体现了外部同步里最关键的几件事：

1. 增量拉取
2. 基于外部 ID 做幂等
3. 同步结果留痕

## 7. 为什么外部 ID 是同步的关键

因为同步不是单纯插入数据，而是：

- 识别“这条外部数据在我本地对应谁”

所以很多同步系统都会给本地表增加：

- `externalId`

或者：

- `sourceSystem + externalId`

作为外部主键映射。

没有这个映射关系，后续同步会非常混乱。

## 8. 全量同步和增量同步怎么选

### 全量同步

适合：

- 初次导入
- 数据量不大
- 周期很低

### 增量同步

适合：

- 日常持续同步
- 数据量较大
- 只希望同步变化部分

正式项目里，通常是：

- 先全量初始化
- 后续走增量同步

## 9. 同步失败为什么一定要有补偿

因为外部系统同步本身就很容易受外部波动影响，例如：

- 对方接口超时
- 对方接口返回脏数据
- 本地落库失败

如果同步失败后没有任何补偿机制，就会出现：

- 某几条数据永远漏同步

所以更成熟的同步体系通常会配：

1. 同步失败日志
2. 重试任务
3. 人工重跑入口

## 10. 常见坑点

### 10.1 没有明确主数据归属

两个系统互相覆盖，很快就会乱。

### 10.2 同步逻辑不幂等

重复同步会产生重复数据或脏数据。

### 10.3 失败后只打日志，不补偿

长期会积累大量数据不一致。

### 10.4 没有同步结果记录

出了问题后很难判断是外部没给、还是本地没接住。

## 11. 总结

外部系统同步的核心，不是“接口打通了”，而是围绕：

- 主数据归属
- 外部主键映射
- 增量同步策略
- 同步幂等
- 失败补偿

建立一套真正可长期运行的数据交换机制。

一个成熟的同步实现至少应该做到：

- 明确主从关系
- 用外部 ID 做映射
- 全量和增量策略清晰
- 同步失败可重试、可追踪

这才是真正稳的系统同步能力。
