# 邮件平台对接实现

## 1. 功能定义

邮件平台对接要解决的问题是：

- 系统如何借助外部邮件服务，把验证码、通知、报表、激活链接等内容稳定地发送给用户

它和前面“邮件发送实现”的区别在于：

- 前面更偏你的系统内部怎么组织邮件能力
- 这一篇更偏你的系统怎么和 SMTP 服务或第三方邮件平台打通

也就是说，这里重点讨论的是：

- 外部邮件通道集成层

## 2. 为什么邮件平台对接也要单独抽象

因为邮件和短信一样，看起来只是“发个通知”，但真正集成时会涉及：

1. 鉴权
2. 发件人配置
3. 模板内容
4. HTML 格式
5. 附件支持
6. 失败重试

如果业务代码直接堆满这些细节，后面会非常难维护。

## 3. 常见邮件通道来源

最常见的邮件通道包括：

1. 企业自建 SMTP
2. 云邮件服务
3. 第三方事务邮件平台

从工程上看，这些通道底层协议和 SDK 不同，但业务侧真正关心的通常只是：

- 发给谁
- 发什么内容
- 成功还是失败

所以更合理的设计通常是把“邮件通道能力”封成统一接口。

## 4. 核心设计

邮件平台对接时，建议重点考虑：

1. 通道是否统一抽象
2. 模板和内容拼装是否分离
3. 是否支持 HTML 和附件
4. 失败结果是否可追踪
5. 发件人和密钥如何管理

其中最重要的一点通常是：

- 邮件内容生成和邮件发送通道最好分层

## 5. 核心代码

## 5.1 邮件通道统一接口

```java
public interface MailPlatformClient {

    MailSendResult send(MailSendRequest request);
}
```

## 5.2 基于 JavaMail 的平台实现示例

```java
@Service
public class SmtpMailPlatformClientImpl implements MailPlatformClient {

    private final JavaMailSender javaMailSender;

    @Value("${spring.mail.username}")
    private String from;

    public SmtpMailPlatformClientImpl(JavaMailSender javaMailSender) {
        this.javaMailSender = javaMailSender;
    }

    @Override
    public MailSendResult send(MailSendRequest request) {
        try {
            MimeMessage mimeMessage = javaMailSender.createMimeMessage();
            MimeMessageHelper helper = new MimeMessageHelper(mimeMessage, true, StandardCharsets.UTF_8.name());
            helper.setFrom(from);
            helper.setTo(request.getTo());
            helper.setSubject(request.getSubject());
            helper.setText(request.getContent(), request.isHtml());
            javaMailSender.send(mimeMessage);

            MailSendResult result = new MailSendResult();
            result.setSuccess(true);
            return result;
        } catch (Exception ex) {
            throw new BizException("邮件平台发送失败");
        }
    }
}
```

这段代码里最重要的不是 `JavaMailSender`，而是：

- 对外暴露的是统一邮件平台接口
- 业务层不直接依赖具体发送实现

## 6. 为什么邮件平台更适合模板化

和短信相比，邮件内容通常更长、更正式，也更容易包含：

- 标题
- 正文模块
- 品牌样式
- 按钮链接
- 附件说明

所以工程上更推荐：

1. 模板引擎生成正文
2. 平台层只负责发送

这样职责会更清晰：

- 模板层决定“发什么”
- 平台层决定“怎么发”

## 7. 失败治理为什么重要

邮件平台集成时，失败通常比成功更值得设计。  
因为常见失败包括：

- SMTP 连接失败
- 平台限流
- 收件地址非法
- 模板渲染异常

成熟的邮件通道集成通常至少会做：

1. 发送日志
2. 失败原因记录
3. 可重试策略
4. 告警联动

## 8. 常见坑点

### 8.1 业务代码里直接构造 MimeMessage

一旦业务多了，会非常乱。

### 8.2 平台发送失败没有日志

后续无法定位是内容问题、通道问题还是账号问题。

### 8.3 所有邮件模板都写死在 Java 代码里

维护成本会越来越高。

## 9. 总结

邮件平台对接的核心，不是“某封邮件发出去了”，而是把邮件发送能力抽象成一个：

- 通道可替换
- 内容可模板化
- 失败可追踪

的外部集成层。

一个成熟的邮件平台对接实现至少应该做到：

- 平台能力统一封装
- 模板与发送分层
- 发送结果可追踪
- 配置和密钥可安全管理

这才是真正适合生产环境长期维护的邮件平台集成方式。
