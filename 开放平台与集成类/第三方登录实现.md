# 第三方登录实现

## 1. 功能定义

第三方登录要解决的问题是：

- 用户不在你的系统里手动注册用户名密码，而是直接使用外部平台的身份登录你的系统

最常见的第三方登录来源包括：

- 微信登录
- QQ 登录
- GitHub 登录
- Google 登录
- 企业微信 / 钉钉统一身份登录

从业务角度看，第三方登录的价值通常在于：

1. 降低注册门槛
2. 提升登录转化率
3. 复用已有身份体系

从工程角度看，它本质上是在做：

- 外部身份认证结果和本地账号体系的映射

## 2. 第三方登录和本地登录的区别

本地登录通常依赖：

- 用户名
- 密码
- 本地用户表

而第三方登录通常依赖：

- 第三方平台授权
- 第三方返回的用户标识
- 本地账号绑定关系

也就是说，第三方登录的真正关键点不是“怎么跳转授权页”，而是：

- 外部身份怎么映射成本地用户

## 3. 最常见的授权模型

绝大多数第三方登录底层都绕不开：

- OAuth2 授权码模式

简化后可以理解成下面这条链路：

1. 用户点击“使用第三方登录”
2. 跳转到第三方授权页
3. 用户同意授权
4. 第三方回调你的系统，并带回 `code`
5. 你的系统拿 `code` 换 `access_token`
6. 再用 `access_token` 换用户身份信息
7. 将第三方身份和本地账号绑定
8. 最终给用户签发你自己系统的登录态

这条流程非常关键，因为它说明了一件事：

- 第三方平台负责认证“你是谁”
- 你自己的系统负责决定“你在我这里是谁”

## 4. 核心设计

第三方登录实现时，建议重点考虑：

1. 第三方唯一标识存什么  
例如 `openid`、`unionId`、`githubId`。

2. 第一次登录怎么处理  
直接自动注册，还是要求绑定已有账号。

3. 一个本地用户是否允许绑定多个第三方账号
4. 解绑逻辑怎么处理
5. 第三方头像、昵称是否同步更新

这里最关键的一点通常是：

- 第三方身份标识和本地用户是两个概念，必须分层

## 5. 典型数据结构

第三方登录通常会单独建一张绑定表，例如：

```json
{
  "id": 1,
  "platform": "GITHUB",
  "platformUserId": "12345678",
  "unionId": null,
  "userId": 101,
  "nickname": "tom",
  "avatar": "https://avatar.example.com/a.png"
}
```

这张表的核心意义是：

- 平台身份
- 本地用户

之间的映射关系被显式保存下来。

## 6. 典型流程

以 GitHub 登录为例，一个比较典型的流程如下：

1. 前端跳转 GitHub 授权页
2. GitHub 回调你的系统并附带 `code`
3. 后端调用 GitHub 接口换取 `access_token`
4. 后端用 `access_token` 获取 GitHub 用户信息
5. 查询本地是否已绑定
6. 如果已绑定，则直接登录
7. 如果未绑定，则自动注册或提示绑定已有账号
8. 签发本地 token

## 7.1 第三方登录请求结果对象

public class ThirdLoginUserInfo {

    private String platform;
    private String platformUserId;
    private String nickname;
    private String avatar;

    public String getPlatform() {
        return platform;
    }

    public void setPlatform(String platform) {
        this.platform = platform;
    }

    public String getPlatformUserId() {
        return platformUserId;
    }

    public void setPlatformUserId(String platformUserId) {
        this.platformUserId = platformUserId;
    }

    public String getNickname() {
        return nickname;
    }

    public void setNickname(String nickname) {
        this.nickname = nickname;
    }

    public String getAvatar() {
        return avatar;
    }

    public void setAvatar(String avatar) {
        this.avatar = avatar;
    }
}

## 7.2 授权码登录核心实现

```java
@Service
public class ThirdLoginServiceImpl implements ThirdLoginService {

    private final ThirdPlatformClient thirdPlatformClient;
    private final UserMapper userMapper;
    private final UserThirdAuthMapper userThirdAuthMapper;
    private final AuthTokenService authTokenService;

    public ThirdLoginServiceImpl(
            ThirdPlatformClient thirdPlatformClient,
            UserMapper userMapper,
            UserThirdAuthMapper userThirdAuthMapper,
            AuthTokenService authTokenService) {
        this.thirdPlatformClient = thirdPlatformClient;
        this.userMapper = userMapper;
        this.userThirdAuthMapper = userThirdAuthMapper;
        this.authTokenService = authTokenService;
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public LoginResult loginByCode(String platform, String code) {
        ThirdLoginUserInfo thirdUser = thirdPlatformClient.queryUserByCode(platform, code);
        if (thirdUser == null) {
            throw new BizException("第三方登录失败");
        }

        UserThirdAuth auth = userThirdAuthMapper.selectByPlatformAndUserId(
                thirdUser.getPlatform(),
                thirdUser.getPlatformUserId()
        );

        Long userId;
        if (auth != null) {
            userId = auth.getUserId();
        } else {
            User user = new User();
            user.setNickname(thirdUser.getNickname());
            user.setAvatar(thirdUser.getAvatar());
            user.setStatus("ENABLE");
            userMapper.insert(user);

            UserThirdAuth bind = new UserThirdAuth();
            bind.setPlatform(thirdUser.getPlatform());
            bind.setPlatformUserId(thirdUser.getPlatformUserId());
            bind.setUserId(user.getId());
            bind.setNickname(thirdUser.getNickname());
            bind.setAvatar(thirdUser.getAvatar());
            userThirdAuthMapper.insert(bind);

            userId = user.getId();
        }

        return authTokenService.createLoginResult(userId);
    }
}
```

这段代码里最重要的事情有三件：

1. 先用授权码拿第三方身份
2. 再查本地是否已有绑定
3. 最终仍然签发你自己系统的登录态

## 8. 为什么第三方登录最后还要签发本地 token

因为第三方平台只负责告诉你：

- 这个人是谁

但后续你系统内部的权限、菜单、订单、资料、审计，都还是基于你自己的用户体系。  
所以正确的思路一定是：

- 第三方负责身份认证
- 本地系统负责会话和权限

## 9. 第一次登录是自动注册还是绑定已有账号

这是第三方登录里一个非常关键的业务决策。

常见做法有两种：

### 9.1 自动注册本地账号

优点：

- 登录体验顺滑

缺点：

- 容易产生很多“轻注册”账号

### 9.2 强制绑定已有账号

优点：

- 账号体系更干净

缺点：

- 登录路径更长

很多正式项目会根据业务场景选择不同策略。

## 10. 常见坑点

### 10.1 直接把第三方平台 token 当成本地登录态

这会让本地权限和会话治理非常混乱。

### 10.2 不单独建绑定表

后续多平台绑定、解绑、账号合并会很麻烦。

### 10.3 没有处理第三方身份唯一性

可能导致一个外部身份绑定到多个本地账号。

### 10.4 没有考虑头像昵称同步策略

有些系统希望首次同步，有些系统希望每次登录更新，需要提前定义规则。

## 11. 总结

第三方登录的核心，不是“接一个 OAuth 回调”，而是围绕外部身份认证、本地账号绑定和本地登录态签发，建立一套清晰可维护的身份映射机制。

一个成熟的第三方登录实现至少应该做到：

- 第三方身份与本地用户解耦
- 绑定关系独立建模
- 首次登录策略明确
- 最终仍由本地系统签发会话

这才是开放平台集成场景下真正稳的第三方登录方案。
