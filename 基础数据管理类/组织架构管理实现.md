# 组织架构管理实现

## 1. 功能定义

组织架构管理要解决的问题是：

- 公司、事业部、中心、部门之间如何形成层级结构
- 用户属于哪个组织节点
- 数据权限、审批流、通讯录等功能如何挂在组织结构上

它通常是很多企业系统的基础底座。

## 2. 典型数据结构

```json
[
  {
    "id": 1,
    "parentId": 0,
    "name": "总公司"
  },
  {
    "id": 2,
    "parentId": 1,
    "name": "技术中心"
  },
  {
    "id": 3,
    "parentId": 2,
    "name": "后端研发部"
  }
]
```

## 3. 核心设计

组织架构本质上是一棵树，所以它和普通 CRUD 的最大区别在于：

1. 有父子层级关系
2. 新增和修改时要校验父节点
3. 删除时通常不能直接删有子节点的数据

## 4. 核心代码

## 4.1 查询组织树

```java
@RestController
@RequestMapping("/org")
public class OrgController {

    private final OrgService orgService;

    public OrgController(OrgService orgService) {
        this.orgService = orgService;
    }

    @GetMapping("/tree")
    public Result<List<OrgTreeVO>> tree() {
        return Result.success(orgService.tree());
    }
}
```

## 4.2 组织树核心实现

```java
@Service
public class OrgServiceImpl implements OrgService {

    private final OrgMapper orgMapper;

    public OrgServiceImpl(OrgMapper orgMapper) {
        this.orgMapper = orgMapper;
    }

    @Override
    public List<OrgTreeVO> tree() {
        List<Org> orgList = orgMapper.selectList(null);
        Map<Long, OrgTreeVO> nodeMap = orgList.stream().collect(Collectors.toMap(
                Org::getId,
                item -> {
                    OrgTreeVO vo = new OrgTreeVO();
                    vo.setId(item.getId());
                    vo.setName(item.getName());
                    vo.setChildren(new ArrayList<>());
                    return vo;
                }
        ));

        List<OrgTreeVO> rootList = new ArrayList<>();
        for (Org org : orgList) {
            OrgTreeVO current = nodeMap.get(org.getId());
            if (org.getParentId() == 0) {
                rootList.add(current);
                continue;
            }
            OrgTreeVO parent = nodeMap.get(org.getParentId());
            if (parent != null) {
                parent.getChildren().add(current);
            }
        }
        return rootList;
    }
}
```

## 5. 删除组织节点时为什么要谨慎

因为组织节点通常会关联很多数据：

- 下级组织
- 用户归属
- 部门信息
- 审批流程

所以删除组织节点前一般要先校验：

1. 有没有子节点
2. 有没有关联用户

如果有，就不应该直接删除。

## 6. 常见坑点

### 6.1 不校验父节点是否存在

容易造出脏树。

### 6.2 允许节点挂到自己的子节点下面

会导致循环结构。

### 6.3 删除节点不校验引用关系

很容易把整条业务链打断。

## 7. 总结

组织架构管理的核心不是“有个 parentId 字段”，而是围绕树形层级做结构校验、树构建和删除保护。这类基础数据一旦设计好，后面的部门、岗位、数据权限都会更好落地。
