# 条件查询实现

## 1. 功能定义

条件查询要解决的问题是：

- 用户希望按某些字段筛选数据，而不是只看全部列表

例如：

- 按名称搜索
- 按状态筛选
- 按时间范围筛选
- 按分类筛选

这是后台管理系统里最常见的列表增强能力。

## 2. 典型请求

```json
{
  "name": "测试",
  "status": 1,
  "startTime": "2026-06-01 00:00:00",
  "endTime": "2026-06-30 23:59:59"
}
```

## 3. 核心设计

条件查询的核心不是“if 越多越好”，而是：

1. 条件对象统一收口
2. 只拼接有值的查询条件
3. 查询条件和分页、排序要能组合

所以工程里一般会把搜索条件单独抽成一个 `QueryRequest`。

## 4. 核心代码

## 4.1 查询条件对象

```java
public class CategoryQueryRequest extends PageRequest {

    private String name;

    private Integer status;

    private LocalDateTime startTime;

    private LocalDateTime endTime;

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public Integer getStatus() {
        return status;
    }

    public void setStatus(Integer status) {
        this.status = status;
    }

    public LocalDateTime getStartTime() {
        return startTime;
    }

    public void setStartTime(LocalDateTime startTime) {
        this.startTime = startTime;
    }

    public LocalDateTime getEndTime() {
        return endTime;
    }

    public void setEndTime(LocalDateTime endTime) {
        this.endTime = endTime;
    }
}
```

## 4.2 条件查询核心实现

```java
@Service
public class CategoryQueryServiceImpl implements CategoryQueryService {

    private final CategoryMapper categoryMapper;

    public CategoryQueryServiceImpl(CategoryMapper categoryMapper) {
        this.categoryMapper = categoryMapper;
    }

    @Override
    public PageResult<CategoryVO> page(CategoryQueryRequest request) {
        Page<Category> page = new Page<>(request.getPageNum(), Math.min(request.getPageSize(), 100L));

        LambdaQueryWrapper<Category> wrapper = new LambdaQueryWrapper<Category>()
                .like(StringUtils.hasText(request.getName()), Category::getName, request.getName())
                .eq(request.getStatus() != null, Category::getStatus, request.getStatus())
                .ge(request.getStartTime() != null, Category::getCreateTime, request.getStartTime())
                .le(request.getEndTime() != null, Category::getCreateTime, request.getEndTime())
                .orderByDesc(Category::getId);

        Page<Category> resultPage = categoryMapper.selectPage(page, wrapper);

        List<CategoryVO> list = resultPage.getRecords().stream().map(item -> {
            CategoryVO vo = new CategoryVO();
            vo.setId(item.getId());
            vo.setName(item.getName());
            vo.setCode(item.getCode());
            vo.setStatus(item.getStatus());
            return vo;
        }).toList();

        return new PageResult<>(list, resultPage.getTotal(), request.getPageNum(), request.getPageSize());
    }
}
```

## 5. 为什么条件查询要“有值才拼条件”

因为搜索条件大多数都是可选项。  
如果你把所有条件都强行写死，查询就会非常僵硬。

正确做法是：

- 前端传了什么，就拼什么
- 没传的字段，不参与查询

这样才能支持灵活组合查询。

## 6. 常见坑点

### 6.1 时间范围只写一半逻辑

很多时候前端可能只传开始时间或只传结束时间，代码要兼容这种情况。

### 6.2 模糊查询和精确查询混乱

像名称通常适合 `like`，状态通常适合 `eq`，不要一股脑都用一个规则。

### 6.3 条件对象直接复用数据库实体

会让接口入参和数据库字段强耦合，后面很难演进。

## 7. 总结

条件查询的工程重点，在于把搜索条件对象化、可选化、组合化。真正成熟的实现，不是写很多 `if`，而是让查询条件能自然地和分页、排序一起协同工作。
