# 系统参数配置实现

## 1. 功能定义

系统参数配置要解决的问题是：

- 把系统中的一些可调整参数从代码里抽出来，在后台动态管理

例如：

- 上传文件大小限制
- 默认分页大小
- 注册是否开放
- 站点名称

## 2. 典型数据结构

```json
{
  "configKey": "system.register.enabled",
  "configValue": "true",
  "configName": "是否开放注册",
  "remark": "true表示开放，false表示关闭"
}
```

## 3. 核心设计

参数配置和字典类似，都是基础配置数据，但它更偏“系统开关和参数值”。

实现时最关键的点是：

1. 用 `configKey` 唯一标识参数
2. 参数值通常以字符串存储
3. 读取要方便，更新后要能快速生效

## 4. 核心代码

## 4.1 参数查询接口

```java
@RestController
@RequestMapping("/config")
public class SysConfigController {

    private final SysConfigService sysConfigService;

    public SysConfigController(SysConfigService sysConfigService) {
        this.sysConfigService = sysConfigService;
    }

    @GetMapping("/{configKey}")
    public Result<String> getValue(@PathVariable String configKey) {
        return Result.success(sysConfigService.getValue(configKey));
    }
}
```

## 4.2 Service 核心实现

```java
@Service
public class SysConfigServiceImpl implements SysConfigService {

    private static final String CONFIG_CACHE_PREFIX = "sys:config:";

    private final SysConfigMapper sysConfigMapper;
    private final StringRedisTemplate stringRedisTemplate;

    public SysConfigServiceImpl(
            SysConfigMapper sysConfigMapper,
            StringRedisTemplate stringRedisTemplate) {
        this.sysConfigMapper = sysConfigMapper;
        this.stringRedisTemplate = stringRedisTemplate;
    }

    @Override
    public String getValue(String configKey) {
        String cacheValue = stringRedisTemplate.opsForValue().get(CONFIG_CACHE_PREFIX + configKey);
        if (cacheValue != null) {
            return cacheValue;
        }

        String value = sysConfigMapper.selectValueByKey(configKey);
        if (value == null) {
            throw new BizException("参数不存在");
        }

        stringRedisTemplate.opsForValue().set(CONFIG_CACHE_PREFIX + configKey, value, Duration.ofHours(1));
        return value;
    }

    @Override
    public void updateValue(String configKey, String configValue) {
        sysConfigMapper.updateValueByKey(configKey, configValue);
        stringRedisTemplate.delete(CONFIG_CACHE_PREFIX + configKey);
    }
}
```

## 5. 为什么系统参数通常存字符串

因为参数类型非常多：

- 布尔值
- 数字
- 文本
- JSON 配置

如果数据库层强行按很多类型拆分，反而会变复杂。  
所以很多系统会统一存成字符串，然后在业务层自行转换。

## 6. 常见坑点

### 6.1 更新参数后不清缓存

会导致配置已经改了，但业务读取仍然是旧值。

### 6.2 参数 key 命名混乱

建议使用统一前缀风格，例如：

- `system.register.enabled`
- `upload.image.maxSize`

### 6.3 把高频业务数据当系统参数存

系统参数适合低频变更配置，不适合承载高频业务数据。

## 7. 总结

系统参数配置的核心，是把可变的系统行为从代码中抽离出来，变成后台可动态维护的数据项。它和字典管理很像，但更偏向配置读取和运行期开关控制。
