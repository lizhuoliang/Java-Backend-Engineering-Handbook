# 树形结构数据管理实现

## 1. 功能定义

树形结构数据管理要解决的问题是：

- 某类基础数据天然存在父子层级关系

例如：

- 分类树
- 行政区划
- 菜单树
- 组织树
- 部门树

这类数据和普通列表的最大区别在于：它不是平铺结构，而是一棵树。

## 2. 典型数据结构

```json
[
  {
    "id": 1,
    "parentId": 0,
    "name": "根节点"
  },
  {
    "id": 2,
    "parentId": 1,
    "name": "一级子节点"
  }
]
```

## 3. 核心设计

树形结构管理最重要的点有 4 个：

1. 节点有 `parentId`
2. 查询时要能组装成树
3. 修改父节点时要防止形成环
4. 删除时要校验是否存在子节点

## 4. 核心代码

## 4.1 查询树结构核心实现

```java
public <T extends TreeNode> List<T> buildTree(List<T> list) {
    Map<Long, T> nodeMap = list.stream().collect(Collectors.toMap(TreeNode::getId, item -> item));
    List<T> rootList = new ArrayList<>();

    for (T node : list) {
        if (node.getParentId() == 0) {
            rootList.add(node);
            continue;
        }
        T parent = nodeMap.get(node.getParentId());
        if (parent != null) {
            parent.getChildren().add(node);
        }
    }

    return rootList;
}
```

这个方法的意义很大，因为菜单树、组织树、部门树都可以复用这套思路。

## 4.2 删除节点前校验子节点

```java
public void deleteNode(Long id) {
    Long childCount = nodeMapper.selectCount(new LambdaQueryWrapper<TreeEntity>()
            .eq(TreeEntity::getParentId, id));
    if (childCount > 0) {
        throw new BizException("当前节点下存在子节点，不能删除");
    }
    nodeMapper.deleteById(id);
}
```

## 4.3 修改父节点时防止成环

```java
public void updateParent(Long id, Long newParentId) {
    if (Objects.equals(id, newParentId)) {
        throw new BizException("父节点不能是自己");
    }

    List<Long> childIds = nodeMapper.selectAllChildIds(id);
    if (childIds.contains(newParentId)) {
        throw new BizException("父节点不能是自己的子节点");
    }

    TreeEntity entity = new TreeEntity();
    entity.setId(id);
    entity.setParentId(newParentId);
    nodeMapper.updateById(entity);
}
```

## 5. 为什么树结构数据要重点防环

因为一旦形成：

```text
A -> B -> C -> A
```

整棵树就会失真，后续：

- 树查询
- 递归遍历
- 数据权限
- 菜单构建

都会出问题。

## 6. 常见坑点

### 6.1 删除节点不校验子节点

容易留下孤儿数据。

### 6.2 修改父节点不做环检测

这是树结构最经典的问题之一。

### 6.3 每个树模块都各写一套构建逻辑

可以抽公共工具复用。

## 7. 总结

树形结构数据管理的核心是围绕层级关系做树构建、删除保护和环检测。它不是某一个业务的专属能力，而是很多基础管理模块的共性骨架。
