# 批量导入实现

## 1. 功能定义

批量导入要解决的问题是：

- 把外部表格数据快速批量写入系统

最常见的导入来源是：

- `Excel`
- `CSV`

典型场景包括：

- 批量导入用户
- 批量导入商品
- 批量导入字典项

## 2. 核心设计

批量导入真正关键的不是“会读 Excel”，而是：

1. 模板字段要固定
2. 每行数据要单独校验
3. 错误信息要能定位到具体行
4. 导入策略要明确：全成功、部分成功还是失败回滚

## 3. 典型流程

1. 用户上传 Excel
2. 后端解析每一行
3. 做格式校验和业务校验
4. 记录失败行和失败原因
5. 批量入库
6. 返回导入结果

## 4. 结果示例

```json
{
  "successCount": 8,
  "failCount": 2,
  "failList": [
    {
      "rowNum": 3,
      "reason": "手机号格式错误"
    },
    {
      "rowNum": 6,
      "reason": "用户名已存在"
    }
  ]

```

## 5. 核心代码

## 5.1 导入服务核心实现

下面用“导入用户”举例。

```java
@Service
public class UserImportServiceImpl implements UserImportService {

    private final UserMapper userMapper;

    public UserImportServiceImpl(UserMapper userMapper) {
        this.userMapper = userMapper;
    }

    @Override
    public ImportResult importUsers(List<UserImportRow> rows) {
        List<User> saveList = new ArrayList<>();
        List<ImportFailItem> failList = new ArrayList<>();

        int rowNum = 1;
        for (UserImportRow row : rows) {
            if (!StringUtils.hasText(row.getUsername())) {
                failList.add(new ImportFailItem(rowNum, "用户名不能为空"));
                rowNum++;
                continue;
            }

            if (!row.getPhone().matches("^1[3-9]\\d{9}$")) {
                failList.add(new ImportFailItem(rowNum, "手机号格式错误"));
                rowNum++;
                continue;
            }

            Long count = userMapper.selectCount(new LambdaQueryWrapper<User>()
                    .eq(User::getUsername, row.getUsername()));
            if (count > 0) {
                failList.add(new ImportFailItem(rowNum, "用户名已存在"));
                rowNum++;
                continue;
            }

            User user = new User();
            user.setUsername(row.getUsername());
            user.setPhone(row.getPhone());
            saveList.add(user);
            rowNum++;
        }

        if (!saveList.isEmpty()) {
            userMapper.batchInsert(saveList);
        }

        return new ImportResult(saveList.size(), failList.size(), failList);
    }
}
```

## 6. 为什么导入功能要返回失败行信息

因为批量导入不是纯技术动作，而是一个强交互业务场景。

如果系统只返回：

```json
{
  "message": "导入失败"
}
```

用户根本不知道哪一行错了，也不知道怎么修。

所以成熟的导入功能一定会告诉用户：

- 第几行错了
- 错在什么地方

## 7. 常见坑点

### 7.1 导入前不校验模板

列顺序、字段名一变，导入结果就会混乱。

### 7.2 一条失败就整批失败

有些场景适合全回滚，但很多后台导入更适合“失败行提示 + 成功行继续导入”。

### 7.3 不限制导入条数

一次性导入几十万行时，很容易拖垮系统。

## 8. 总结

批量导入的工程重点不在文件解析本身，而在校验、错误定位、导入策略和用户反馈。一个好用的导入功能，必须让用户知道“哪一行为什么失败”，而不只是告诉他“失败了”。
