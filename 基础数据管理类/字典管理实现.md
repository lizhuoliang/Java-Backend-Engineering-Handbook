# 字典管理实现

## 1. 功能定义

字典管理通常用于维护系统中的“可配置枚举值”，例如：

- 性别
- 状态
- 订单类型
- 文章分类

它的目标是把这些经常变化、需要后台维护的选项从代码里抽出来。

## 2. 典型数据结构

字典一般分成两层：

1. 字典类型
2. 字典项

```json
{
  "dictType": "user_gender",
  "dictName": "用户性别",
  "items": [
    {
      "label": "男",
      "value": "1",
      "sort": 1
    },
    {
      "label": "女",
      "value": "2",
      "sort": 2
    }
  ]
}
```

## 3. 核心设计

字典管理最重要的点有 3 个：

1. 类型和项分表管理
2. 字典项要支持排序、启用禁用
3. 前端通常按 `dictType` 拉取字典项列表

## 4. 核心代码

## 4.1 查询字典项接口

```java
@RestController
@RequestMapping("/dict")
public class DictController {

    private final DictService dictService;

    public DictController(DictService dictService) {
        this.dictService = dictService;
    }

    @GetMapping("/items/{dictType}")
    public Result<List<DictItemVO>> items(@PathVariable String dictType) {
        return Result.success(dictService.getItemsByType(dictType));
    }
}
```

## 4.2 Service 核心实现

```java
@Service
public class DictServiceImpl implements DictService {

    private static final String DICT_CACHE_PREFIX = "dict:";

    private final DictItemMapper dictItemMapper;
    private final StringRedisTemplate stringRedisTemplate;

    public DictServiceImpl(
            DictItemMapper dictItemMapper,
            StringRedisTemplate stringRedisTemplate) {
        this.dictItemMapper = dictItemMapper;
        this.stringRedisTemplate = stringRedisTemplate;
    }

    @Override
    public List<DictItemVO> getItemsByType(String dictType) {
        String cache = stringRedisTemplate.opsForValue().get(DICT_CACHE_PREFIX + dictType);
        if (cache != null) {
            return JSON.parseArray(cache, DictItemVO.class);
        }

        List<DictItemVO> list = dictItemMapper.selectEnabledItemsByType(dictType);
        stringRedisTemplate.opsForValue().set(
                DICT_CACHE_PREFIX + dictType,
                JSON.toJSONString(list),
                Duration.ofHours(1)
        );
        return list;
    }
}
```

## 5. 为什么字典适合加缓存

因为字典数据通常有这些特点：

- 读多写少
- 数据量小
- 高频复用

比如性别、状态、类型这些值，在很多页面都会反复使用。

所以把字典项缓存到 Redis 非常常见。

## 6. 常见坑点

### 6.1 字典写死在代码里

后面一旦要改显示文案、顺序、状态，就必须重新发版。

### 6.2 字典更新后不清缓存

前端会一直看到旧值。

### 6.3 类型和值没有唯一约束

容易出现重复字典项，导致前端展示混乱。

## 7. 总结

字典管理的核心，是把系统里的“固定选项集”从代码中抽离出来，变成可维护、可排序、可缓存的后台基础数据。这是很多后台系统必备的通用能力。
