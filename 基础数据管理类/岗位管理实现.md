# 岗位管理实现

## 1. 功能定义

岗位管理主要解决：

- 用户在组织中的岗位是什么
- 某些业务流程如何按岗位流转
- 某些权限是否与岗位有关

岗位和角色不是一回事：

- 角色更偏系统权限
- 岗位更偏组织职责

## 2. 典型数据结构

```json
{
  "id": 1,
  "postCode": "backend_dev",
  "postName": "后端开发工程师",
  "sort": 10,
  "status": 1
}
```

## 3. 核心设计

岗位管理通常比部门简单，更多是一个标准字典化管理：

1. 岗位编码唯一
2. 岗位名称可维护
3. 支持排序和启用禁用

## 4. 核心代码

## 4.1 新增岗位核心实现

```java
@Service
public class PostServiceImpl implements PostService {

    private final PostMapper postMapper;

    public PostServiceImpl(PostMapper postMapper) {
        this.postMapper = postMapper;
    }

    @Override
    public void add(PostAddRequest request) {
        Long count = postMapper.selectCount(new LambdaQueryWrapper<Post>()
                .eq(Post::getPostCode, request.getPostCode()));
        if (count > 0) {
            throw new BizException("岗位编码已存在");
        }

        Post post = new Post();
        post.setPostCode(request.getPostCode());
        post.setPostName(request.getPostName());
        post.setSort(request.getSort());
        post.setStatus(request.getStatus());
        postMapper.insert(post);
    }
}
```

## 4.2 分页查询岗位核心实现

```java
@Override
public PageResult<PostVO> page(PostQueryRequest request) {
    Page<Post> page = new Page<>(request.getPageNum(), Math.min(request.getPageSize(), 100L));
    Page<Post> resultPage = postMapper.selectPage(page, new LambdaQueryWrapper<Post>()
            .like(StringUtils.hasText(request.getPostName()), Post::getPostName, request.getPostName())
            .eq(request.getStatus() != null, Post::getStatus, request.getStatus())
            .orderByAsc(Post::getSort)
            .orderByDesc(Post::getId));

    List<PostVO> list = resultPage.getRecords().stream().map(item -> {
        PostVO vo = new PostVO();
        vo.setId(item.getId());
        vo.setPostCode(item.getPostCode());
        vo.setPostName(item.getPostName());
        vo.setStatus(item.getStatus());
        return vo;
    }).toList();

    return new PageResult<>(list, resultPage.getTotal(), request.getPageNum(), request.getPageSize());
}
```

## 5. 岗位和角色为什么要区分

因为它们解决的问题完全不同。

例如一个“部门经理”：

- 岗位是 `dept_manager`
- 角色可能是 `approval_operator`

也就是说：

- 岗位描述组织职责
- 角色描述系统能力

不要把两者混成一套概念。

## 6. 常见坑点

### 6.1 用岗位替代权限角色

这样后面一旦系统权限复杂，就会变得非常混乱。

### 6.2 岗位编码不做唯一限制

容易出现重复岗位标识。

### 6.3 用户和岗位关系设计过死

有些系统一个用户可能会兼任多个岗位，建模时要考虑业务实际。

## 7. 总结

岗位管理本质上是组织职责维度的基础数据管理。它通常不复杂，但在审批流、通讯录、人员组织关系这些场景里非常重要。
