# 排序实现

## 1. 功能定义

排序要解决的问题是：

- 列表数据以什么顺序展示

后台系统里常见的排序包括：

- 按创建时间倒序
- 按更新时间倒序
- 按编号升序
- 按手工排序字段升序

排序看起来只是查询附带的一点逻辑，但如果处理不好，很容易带来接口不稳定甚至安全问题。

## 2. 典型请求

```json
{
  "pageNum": 1,
  "pageSize": 10,
  "orderBy": "createTime",
  "orderDirection": "desc"
}
```

## 3. 核心设计

排序实现最关键的点不是“能不能传排序字段”，而是：

1. 排序字段不能完全信任前端
2. 要做白名单映射
3. 必须有默认排序

如果前端传什么字段就直接拼进 SQL，很容易出问题。

## 4. 核心代码

## 4.1 排序请求对象

```java
public class SortPageRequest extends PageRequest {

    private String orderBy;

    private String orderDirection;

    public String getOrderBy() {
        return orderBy;
    }

    public void setOrderBy(String orderBy) {
        this.orderBy = orderBy;
    }

    public String getOrderDirection() {
        return orderDirection;
    }

    public void setOrderDirection(String orderDirection) {
        this.orderDirection = orderDirection;
    }
}
```

## 4.2 排序核心实现

```java
@Service
public class CategoryQueryServiceImpl implements CategoryQueryService {

    private static final Map<String, SFunction<Category, ?>> SORT_FIELD_MAP = Map.of(
            "id", Category::getId,
            "name", Category::getName,
            "createTime", Category::getCreateTime,
            "sort", Category::getSort
    );

    private final CategoryMapper categoryMapper;

    public CategoryQueryServiceImpl(CategoryMapper categoryMapper) {
        this.categoryMapper = categoryMapper;
    }

    @Override
    public PageResult<CategoryVO> page(SortPageRequest request) {
        LambdaQueryWrapper<Category> wrapper = new LambdaQueryWrapper<>();

        SFunction<Category, ?> sortField = SORT_FIELD_MAP.getOrDefault(request.getOrderBy(), Category::getId);
        boolean asc = "asc".equalsIgnoreCase(request.getOrderDirection());

        wrapper.orderBy(true, asc, sortField);

        Page<Category> page = new Page<>(request.getPageNum(), Math.min(request.getPageSize(), 100L));
        Page<Category> resultPage = categoryMapper.selectPage(page, wrapper);

        List<CategoryVO> list = resultPage.getRecords().stream().map(item -> {
            CategoryVO vo = new CategoryVO();
            vo.setId(item.getId());
            vo.setName(item.getName());
            return vo;
        }).toList();

        return new PageResult<>(list, resultPage.getTotal(), request.getPageNum(), request.getPageSize());
    }
}
```

## 5. 为什么排序字段要做白名单

如果直接信任前端传入：

```json
{
  "orderBy": "任意SQL片段"
}
```

就可能带来 SQL 注入风险，或者至少会让接口行为不可控。

所以更稳的做法是：

- 前端传“逻辑字段名”
- 后端映射到允许排序的真实字段

## 6. 常见坑点

### 6.1 没有默认排序

会导致同一个分页列表每次返回顺序不稳定。

### 6.2 排序字段完全信任前端

这既不安全，也不利于维护。

### 6.3 多字段排序规则不清

如果要支持多字段排序，最好统一约定格式，不要临时拼字符串。

## 7. 总结

排序实现的关键，不是“支持前端传字段”，而是通过默认排序和白名单映射，让列表结果稳定、安全、可控。这一点在所有基础列表接口里都非常重要。
