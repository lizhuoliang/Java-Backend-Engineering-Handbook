# 分页查询实现

## 1. 功能定义

分页查询要解决的问题是：

- 数据量很多时，不能一次性全部返回
- 前端需要按页浏览数据

后台系统里几乎所有列表页都会用到分页，所以这是基础数据管理里非常核心的一项能力。

## 2. 典型请求

```json
{
  "pageNum": 1,
  "pageSize": 10
}
```

## 3. 返回示例

```json
{
  "list": [
    {
      "id": 1,
      "name": "分类A"
    }
  ],
  "total": 58,
  "pageNum": 1,
  "pageSize": 10
}
```

## 4. 核心设计

分页查询最重要的点有 3 个：

1. 前后端统一页码规则  
通常约定 `pageNum` 从 `1` 开始。

2. 限制单页大小  
防止有人一次查 `100000` 条把系统打挂。

3. 返回总数和当前页数据  
前端做分页器必须依赖这两个信息。

## 5. 核心代码

## 5.1 分页请求对象

```java
public class PageRequest {

    @NotNull(message = "页码不能为空")
    private Long pageNum;

    @NotNull(message = "每页条数不能为空")
    private Long pageSize;

    public Long getPageNum() {
        return pageNum;
    }

    public void setPageNum(Long pageNum) {
        this.pageNum = pageNum;
    }

    public Long getPageSize() {
        return pageSize;
    }

    public void setPageSize(Long pageSize) {
        this.pageSize = pageSize;
    }
}
```

## 5.2 分页查询核心实现

这里用 `MyBatis-Plus` 的分页能力做最常见的实现。

```java
@Service
public class CategoryQueryServiceImpl implements CategoryQueryService {

    private final CategoryMapper categoryMapper;

    public CategoryQueryServiceImpl(CategoryMapper categoryMapper) {
        this.categoryMapper = categoryMapper;
    }

    @Override
    public PageResult<CategoryVO> page(PageRequest request) {
        long pageNum = request.getPageNum();
        long pageSize = Math.min(request.getPageSize(), 100L);

        Page<Category> page = new Page<>(pageNum, pageSize);
        Page<Category> resultPage = categoryMapper.selectPage(page, new LambdaQueryWrapper<Category>()
                .orderByDesc(Category::getId));

        List<CategoryVO> list = resultPage.getRecords().stream().map(item -> {
            CategoryVO vo = new CategoryVO();
            vo.setId(item.getId());
            vo.setName(item.getName());
            vo.setCode(item.getCode());
            return vo;
        }).toList();

        return new PageResult<>(list, resultPage.getTotal(), pageNum, pageSize);
    }
}
```

## 6. PageResult 示例

```json
{
  "list": [],
  "total": 0,
  "pageNum": 1,
  "pageSize": 10
}
```

它本质上就是一个统一分页返回结构，不需要很复杂。

## 7. 为什么分页必须限制 pageSize

如果接口完全信任前端，别人直接传：

```json
{
  "pageNum": 1,
  "pageSize": 1000000
}
```

数据库和应用层都可能被拖垮。

所以工程里通常会做：

- 默认值控制
- 最大页大小限制

## 8. 常见坑点

### 8.1 不返回 total

前端分页器通常需要知道总条数。

### 8.2 pageSize 不做限制

容易引发慢查询和内存压力。

### 8.3 分页和排序规则不稳定

如果没有固定排序，同一页数据可能前后刷新顺序变化。

## 9. 总结

分页查询的核心，是把大数据列表切成稳定、可控、可浏览的小块数据返回给前端。真正的工程重点不在分页语法，而在页码规则、返回结构、排序稳定性和单页大小控制。
