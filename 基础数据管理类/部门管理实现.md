# 部门管理实现

## 1. 功能定义

部门管理通常建立在组织架构之下，主要解决：

- 公司内部有哪些部门
- 部门负责人是谁
- 用户属于哪个部门
- 数据权限如何按部门划分

## 2. 典型数据结构

```json
{
  "id": 10,
  "parentId": 2,
  "deptName": "后端研发部",
  "leaderUserId": 101,
  "status": 1
}
```

## 3. 核心设计

部门管理和组织架构管理很像，也是一棵树，但它更贴近人员管理和权限管理。

实现时重点关注：

1. 部门层级关系
2. 部门负责人
3. 部门启用禁用状态

## 4. 核心代码

## 4.1 新增部门核心实现

```java
@Service
public class DeptServiceImpl implements DeptService {

    private final DeptMapper deptMapper;

    public DeptServiceImpl(DeptMapper deptMapper) {
        this.deptMapper = deptMapper;
    }

    @Override
    public void add(DeptAddRequest request) {
        if (request.getParentId() != 0) {
            Dept parent = deptMapper.selectById(request.getParentId());
            if (parent == null) {
                throw new BizException("父部门不存在");
            }
        }

        Dept dept = new Dept();
        dept.setParentId(request.getParentId());
        dept.setDeptName(request.getDeptName());
        dept.setLeaderUserId(request.getLeaderUserId());
        dept.setStatus(request.getStatus());
        deptMapper.insert(dept);
    }
}
```

## 4.2 查询部门树核心实现

```java
@Override
public List<DeptTreeVO> tree() {
    List<Dept> deptList = deptMapper.selectList(null);
    Map<Long, DeptTreeVO> nodeMap = deptList.stream().collect(Collectors.toMap(
            Dept::getId,
            item -> {
                DeptTreeVO vo = new DeptTreeVO();
                vo.setId(item.getId());
                vo.setDeptName(item.getDeptName());
                vo.setChildren(new ArrayList<>());
                return vo;
            }
    ));

    List<DeptTreeVO> rootList = new ArrayList<>();
    for (Dept dept : deptList) {
        DeptTreeVO current = nodeMap.get(dept.getId());
        if (dept.getParentId() == 0) {
            rootList.add(current);
            continue;
        }
        DeptTreeVO parent = nodeMap.get(dept.getParentId());
        if (parent != null) {
            parent.getChildren().add(current);
        }
    }
    return rootList;
}
```

## 5. 部门为什么是数据权限的关键基础

因为很多企业系统里的数据范围规则就是围绕部门来的：

- 本部门可见
- 本部门及子部门可见

所以部门层级一旦设计不规范，后面的数据权限就很难做对。

## 6. 常见坑点

### 6.1 部门树和组织树职责混乱

如果系统里同时有“组织”和“部门”，一定要定义清楚边界。

### 6.2 删除部门不检查员工归属

很容易造成大量用户挂到无效部门上。

### 6.3 禁用父部门但子部门仍然启用

这种情况通常要提前定义系统规则。

## 7. 总结

部门管理的工程重点在于层级关系、负责人和人员归属。它不只是一个树结构模块，更是权限、流程和通讯录等能力的重要基础数据来源。
