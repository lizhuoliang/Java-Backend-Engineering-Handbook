# 密码修改与找回实现

## 1. 功能定义

密码相关功能通常至少有两类：

1. 已登录用户修改密码
2. 未登录用户找回密码

这两个场景很像，但核心逻辑不同：

- 修改密码：重点是校验旧密码
- 找回密码：重点是校验身份，例如短信验证码、邮箱验证码

## 2. 典型流程

### 2.1 修改密码

1. 当前用户输入旧密码、新密码、确认密码
2. 后端校验旧密码是否正确
3. 校验两次新密码是否一致
4. 加密保存新密码
5. 清理当前用户的登录态

### 2.2 找回密码

1. 用户输入手机号或邮箱
2. 输入验证码
3. 输入新密码和确认密码
4. 后端校验验证码
5. 加密保存新密码
6. 清理该用户旧登录态

## 3. 请求示例

### 3.1 修改密码

```json
{
  "oldPassword": "old123456",
  "newPassword": "new123456",
  "confirmPassword": "new123456"
}
```

### 3.2 找回密码

```json
{
  "phone": "13800000000",
  "verifyCode": "9527",
  "newPassword": "new123456",
  "confirmPassword": "new123456"
}
```

## 4. 核心代码

## 4.1 修改密码请求对象

```java
public class UpdatePasswordRequest {

    @NotBlank(message = "旧密码不能为空")
    private String oldPassword;

    @NotBlank(message = "新密码不能为空")
    private String newPassword;

    @NotBlank(message = "确认密码不能为空")
    private String confirmPassword;

    public String getOldPassword() {
        return oldPassword;
    }

    public void setOldPassword(String oldPassword) {
        this.oldPassword = oldPassword;
    }

    public String getNewPassword() {
        return newPassword;
    }

    public void setNewPassword(String newPassword) {
        this.newPassword = newPassword;
    }

    public String getConfirmPassword() {
        return confirmPassword;
    }

    public void setConfirmPassword(String confirmPassword) {
        this.confirmPassword = confirmPassword;
    }
}
```

## 4.2 修改密码核心实现

```java
@Service
public class PasswordServiceImpl implements PasswordService {

    private final UserMapper userMapper;
    private final PasswordEncoder passwordEncoder;
    private final LoginSessionService loginSessionService;

    public PasswordServiceImpl(
            UserMapper userMapper,
            PasswordEncoder passwordEncoder,
            LoginSessionService loginSessionService) {
        this.userMapper = userMapper;
        this.passwordEncoder = passwordEncoder;
        this.loginSessionService = loginSessionService;
    }

    @Override
    public void updatePassword(Long userId, UpdatePasswordRequest request) {
        if (!request.getNewPassword().equals(request.getConfirmPassword())) {
            throw new BizException("两次输入的新密码不一致");
        }

        User user = userMapper.selectById(userId);
        if (user == null) {
            throw new BizException("用户不存在");
        }

        if (!passwordEncoder.matches(request.getOldPassword(), user.getPassword())) {
            throw new BizException("旧密码错误");
        }

        User updateUser = new User();
        updateUser.setId(userId);
        updateUser.setPassword(passwordEncoder.encode(request.getNewPassword()));
        userMapper.updateById(updateUser);

        loginSessionService.clearByUserId(userId);
    }
}
```

这里最后一步很重要：

- 修改密码后，最好清理当前用户全部旧登录态

否则旧 `token` 仍然可能继续使用。

## 4.3 找回密码核心实现

```java
@Service
public class PasswordServiceImpl implements PasswordService {

    private final UserMapper userMapper;
    private final PasswordEncoder passwordEncoder;
    private final VerifyCodeService verifyCodeService;
    private final LoginSessionService loginSessionService;

    @Override
    public void resetPasswordByPhone(ResetPasswordRequest request) {
        if (!request.getNewPassword().equals(request.getConfirmPassword())) {
            throw new BizException("两次输入的新密码不一致");
        }

        verifyCodeService.validateResetCode(request.getPhone(), request.getVerifyCode());

        User user = userMapper.selectOne(new LambdaQueryWrapper<User>()
                .eq(User::getPhone, request.getPhone()));
        if (user == null) {
            throw new BizException("用户不存在");
        }

        User updateUser = new User();
        updateUser.setId(user.getId());
        updateUser.setPassword(passwordEncoder.encode(request.getNewPassword()));
        userMapper.updateById(updateUser);

        verifyCodeService.removeResetCode(request.getPhone());
        loginSessionService.clearByUserId(user.getId());
    }
}
```

## 5. 会话清理核心思路

密码被修改后，原有会话最好统一失效。

例如可以维护：

```json
{
  "userId": 1,
  "tokens": [
    "tokenA",
    "tokenB"
  ]
}
```

然后在 `clearByUserId(userId)` 中删除该用户关联的全部 `token` 登录态。

## 6. 为什么密码操作一定要让旧登录态失效

因为密码变化本身就意味着身份边界发生了变化。

如果不清理旧会话，可能出现：

- 密码已经改了
- 但旧设备上的登录状态仍然有效

这在安全上是不合理的。

## 7. 常见坑点

### 7.1 新密码直接明文入库

必须继续使用 `PasswordEncoder` 加密保存。

### 7.2 修改密码后不清理登录态

会导致旧 `token` 继续可用。

### 7.3 找回密码不做验证码校验

这样等于任何人知道手机号都能改密码。

### 7.4 不校验两次新密码一致性

这是很基础但很容易漏掉的一步。

## 8. 总结

密码修改与找回的核心，不只是“把 password 字段改掉”，而是围绕身份安全完成一整套闭环：

- 修改密码要校验旧密码
- 找回密码要校验验证码
- 新密码要加密保存
- 密码变更后要清理旧登录态

这几步缺一不可。
