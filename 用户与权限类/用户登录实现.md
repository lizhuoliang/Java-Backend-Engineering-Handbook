# 用户登录实现

## 1. 功能定义

用户登录的目标，是让系统确认“你是谁”，并在确认成功后签发一个后续可访问系统的身份凭证。

在工程化项目里，登录功能不只是校验用户名和密码，还要同时处理下面这些问题：

- 账号是否存在
- 密码是否正确
- 账号是否被禁用
- 登录成功后如何生成身份凭证
- 登录态存在哪里
- 后续请求如何识别用户
- 是否支持退出登录、踢下线、单端登录

本文采用最常见的一套方案：

- `Spring Boot`
- `MyBatis-Plus`
- `MySQL`
- `Redis`
- `JWT`

## 2. 典型登录流程

一个标准的用户名密码登录流程通常是这样：

1. 前端提交用户名和密码
2. 后端查询用户
3. 校验密码
4. 校验账号状态
5. 生成 `token`
6. 将登录态写入 `Redis`
7. 返回 `token`

## 4. 登录实现的核心设计

登录功能最关键的不是代码量，而是这几个核心决策：

1. 密码必须存加密值，不能明文比对
2. 登录成功后不能只返回“成功”，而是要签发 `token`
3. `token` 需要配合 `Redis` 保存登录态，便于做退出登录、续期、踢下线
4. 登录时除了校验密码，还要校验用户状态

## 5. 核心代码

## 5.1 Controller

Controller 层只负责接收请求和调用登录服务。

```java
@RestController
@RequestMapping("/auth")
public class AuthController {

    private final AuthService authService;

    public AuthController(AuthService authService) {
        this.authService = authService;
    }

    @PostMapping("/login")
    public Result<Map<String, Object>> login(@RequestBody @Valid LoginRequest request) {
        return Result.success(authService.login(request));
    }
}
```

## 5.2 登录请求对象

这里只保留最小必要字段。

```java
public class LoginRequest {

    @NotBlank(message = "用户名不能为空")
    private String username;

    @NotBlank(message = "密码不能为空")
    private String password;

    public String getUsername() {
        return username;
    }

    public void setUsername(String username) {
        this.username = username;
    }

    public String getPassword() {
        return password;
    }

    public void setPassword(String password) {
        this.password = password;
    }
}
```

## 5.3 Service 接口

```java
public interface AuthService {

    Map<String, Object> login(LoginRequest request);
}
```

## 5.4 Service 核心实现

这一段是登录实现里最核心的部分。

```java
@Service
public class AuthServiceImpl implements AuthService {

    private static final long EXPIRE_SECONDS = 7200L;

    private final UserMapper userMapper;
    private final PasswordEncoder passwordEncoder;
    private final StringRedisTemplate stringRedisTemplate;
    private final JwtTokenProvider jwtTokenProvider;

    public AuthServiceImpl(
            UserMapper userMapper,
            PasswordEncoder passwordEncoder,
            StringRedisTemplate stringRedisTemplate,
            JwtTokenProvider jwtTokenProvider) {
        this.userMapper = userMapper;
        this.passwordEncoder = passwordEncoder;
        this.stringRedisTemplate = stringRedisTemplate;
        this.jwtTokenProvider = jwtTokenProvider;
    }

    @Override
    public Map<String, Object> login(LoginRequest request) {
        User user = userMapper.selectOne(new LambdaQueryWrapper<User>()
                .eq(User::getUsername, request.getUsername()));

        if (user == null) {
            throw new BizException("用户名或密码错误");
        }

        if (!passwordEncoder.matches(request.getPassword(), user.getPassword())) {
            throw new BizException("用户名或密码错误");
        }

        if (user.getStatus() == null || user.getStatus() != 1) {
            throw new BizException("账号已被禁用");
        }

        String token = jwtTokenProvider.createToken(user.getId(), user.getUsername());

        String redisKey = "login:token:" + token;
        String redisValue = JSON.toJSONString(Map.of(
                "userId", user.getId(),
                "username", user.getUsername()
        ));

        stringRedisTemplate.opsForValue().set(redisKey, redisValue, Duration.ofSeconds(EXPIRE_SECONDS));

        return Map.of(
                "token", token,
                "tokenType", "Bearer",
                "expireSeconds", EXPIRE_SECONDS
        );
    }
}
```

这段代码做了 4 件真正重要的事：

- 查用户
- 验密码
- 验状态
- 发 `token` 并缓存登录态

## 5.5 Token 生成核心代码

这里不展开完整 `JWT` 工具类，只保留最关键的方法。

```java
@Component
public class JwtTokenProvider {

    private static final String SECRET = "replace-with-your-secret-key";
    private static final long EXPIRE_MILLIS = 7200_000L;

    public String createToken(Long userId, String username) {
        Date now = new Date();
        Date expire = new Date(now.getTime() + EXPIRE_MILLIS);

        return Jwts.builder()
                .setSubject(String.valueOf(userId))
                .claim("username", username)
                .setIssuedAt(now)
                .setExpiration(expire)
                .signWith(Keys.hmacShaKeyFor(SECRET.getBytes(StandardCharsets.UTF_8)), SignatureAlgorithm.HS256)
                .compact();
    }
}
```

登录功能里，`JWT` 的作用是生成一个可携带身份信息的凭证。  
真正的可控登录态，仍然建议放在 `Redis` 里。

## 6. 为什么还要用 Redis

很多初学者会问：既然已经有 `JWT` 了，为什么还要 Redis？

因为纯 `JWT` 虽然省事，但不方便做下面这些事情：

- 主动退出登录
- 强制踢下线
- 单端登录
- 修改密码后让旧 `token` 失效
- 动态续期

所以工程上更常见的做法是：

- `JWT` 负责给前端一个身份凭证
- `Redis` 负责保存当前登录态

## 7. 登录成功后的 Redis 数据示例

```json
{
  "key": "login:token:eyJhbGciOiJIUzI1NiJ9.xxx.xxx",
  "value": {
    "userId": 1,
    "username": "zhangsan"
  },
  "ttl": 7200
}
```

如果后面要扩展权限校验，也可以把角色、权限标识一并缓存进去。

## 8. 登录校验的关键点

### 8.1 错误提示不要太具体

用户名不存在和密码错误，通常统一返回：

```json
{
  "code": 500,
  "message": "用户名或密码错误"
}
```

不要返回：

- 用户名不存在
- 密码错误

因为这会给攻击者更多试探空间。

### 8.2 禁用状态一定要单独判断

密码对了不代表能登录。  
账号禁用、冻结、注销，都应该在密码校验后继续判断。

### 8.3 密码比较必须用 `PasswordEncoder`

不要自己做字符串比较，也不要手写 `MD5`。  
应该使用：

```java
passwordEncoder.matches(rawPassword, encodedPassword)
```

## 9. 认证流程在后续请求里怎么走

登录只是第一步，后面的接口一般还要这样做：

1. 前端在请求头里带上 `Authorization: Bearer token`
2. 后端拦截器或过滤器解析 `token`
3. 去 Redis 校验该 `token` 是否仍然有效
4. 解析当前用户信息，放入上下文
5. 业务接口继续执行

所以从工程角度看，登录功能实际上是“认证体系”的入口。

## 10. 常见坑点

### 10.1 只生成 JWT，不存 Redis

这样退出登录和踢下线会很麻烦。

### 10.2 把密码明文存库

这是严重安全问题。

### 10.3 返回错误信息过于精确

容易被撞库脚本利用。

### 10.4 登录成功不设置过期时间

会导致 Redis 登录态无限存在。

### 10.5 登录后不做状态校验

被禁用用户仍然可能登录成功。

## 11. 面试中常见问法

### 11.1 用户登录你会怎么实现

回答重点：

- 用户查询
- 密码加密比对
- 用户状态校验
- `JWT` 签发
- `Redis` 保存登录态

### 11.2 为什么 JWT 还要配合 Redis

回答重点：

- 方便退出登录
- 方便踢下线
- 方便控制会话失效
- 方便做动态续期

### 11.3 登录和注册的核心区别是什么

注册核心是“创建用户”；  
登录核心是“校验身份并签发凭证”。

## 12. 总结

一个工程化的用户登录实现，核心不是写很多代码，而是把这条链路设计完整：

前端提交账号密码，后端查询用户并校验密码和状态，登录成功后生成 `JWT`，同时把登录态存入 `Redis`，最终返回可用于后续访问的 `token`。

这一套设计，已经足够支撑大部分 Java 后端项目的基础登录功能。
