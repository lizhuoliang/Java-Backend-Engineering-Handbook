# 用户资料管理实现

## 1. 功能定义

用户资料管理要解决的问题是：

- 用户如何查看自己的基础信息
- 用户如何修改昵称、头像、邮箱、手机号等资料

它和“用户管理”不同：

- 用户管理通常是管理员管理别人
- 用户资料管理通常是用户维护自己

所以这里的核心不是复杂权限，而是：

- 当前用户信息读取
- 可修改字段边界
- 更新校验

## 2. 典型资料字段

```json
{
  "userId": 1,
  "username": "zhangsan",
  "nickname": "张三",
  "avatar": "https://example.com/avatar.png",
  "phone": "13800000000",
  "email": "zhangsan@example.com",
  "gender": 1,
  "remark": "个人简介"
}
```

## 3. 核心设计

用户资料管理通常分成两个接口：

1. 查询当前用户资料
2. 更新当前用户资料

这里有一个工程上很重要的原则：

- 用户能改自己的展示资料
- 但通常不能改用户名、角色、状态这类敏感字段

所以更新接口一定要明确哪些字段可改，哪些字段不可改。

## 4. 核心代码

## 4.1 查询资料接口

```java
@RestController
@RequestMapping("/user/profile")
public class UserProfileController {

    private final UserProfileService userProfileService;

    public UserProfileController(UserProfileService userProfileService) {
        this.userProfileService = userProfileService;
    }

    @GetMapping
    public Result<UserProfileVO> getProfile() {
        Long userId = UserContext.get().getUserId();
        return Result.success(userProfileService.getProfile(userId));
    }
}
```

## 4.2 更新资料请求对象

这里只保留典型可编辑字段。

```java
public class UpdateProfileRequest {

    @NotBlank(message = "昵称不能为空")
    private String nickname;

    private String avatar;

    @Email(message = "邮箱格式不正确")
    private String email;

    @Pattern(regexp = "^1[3-9]\\d{9}$", message = "手机号格式不正确")
    private String phone;

    private Integer gender;

    private String remark;

    public String getNickname() {
        return nickname;
    }

    public void setNickname(String nickname) {
        this.nickname = nickname;
    }

    public String getAvatar() {
        return avatar;
    }

    public void setAvatar(String avatar) {
        this.avatar = avatar;
    }

    public String getEmail() {
        return email;
    }

    public void setEmail(String email) {
        this.email = email;
    }

    public String getPhone() {
        return phone;
    }

    public void setPhone(String phone) {
        this.phone = phone;
    }

    public Integer getGender() {
        return gender;
    }

    public void setGender(Integer gender) {
        this.gender = gender;
    }

    public String getRemark() {
        return remark;
    }

    public void setRemark(String remark) {
        this.remark = remark;
    }
}
```

## 4.3 更新资料接口

```java
@PutMapping
public Result<Void> updateProfile(@RequestBody @Valid UpdateProfileRequest request) {
    Long userId = UserContext.get().getUserId();
    userProfileService.updateProfile(userId, request);
    return Result.success();
}
```

## 4.4 Service 核心实现

```java
@Service
public class UserProfileServiceImpl implements UserProfileService {

    private final UserMapper userMapper;

    public UserProfileServiceImpl(UserMapper userMapper) {
        this.userMapper = userMapper;
    }

    @Override
    public UserProfileVO getProfile(Long userId) {
        return userMapper.selectProfileByUserId(userId);
    }

    @Override
    public void updateProfile(Long userId, UpdateProfileRequest request) {
        User user = new User();
        user.setId(userId);
        user.setNickname(request.getNickname());
        user.setAvatar(request.getAvatar());
        user.setEmail(request.getEmail());
        user.setPhone(request.getPhone());
        user.setGender(request.getGender());
        user.setRemark(request.getRemark());
        userMapper.updateById(user);
    }
}
```

## 5. 为什么更新资料不能直接整对象覆盖

因为资料页通常只允许修改一部分字段。  
如果前端把完整用户对象传回来再整条覆盖，容易带来两个问题：

1. 敏感字段被误改  
例如用户名、状态、角色编号等本不该被修改的字段被覆盖掉。

2. 脏数据覆盖  
前端拿到的是旧数据，回传时可能把新值覆盖没了。

所以工程上更推荐：

- 明确一个“资料修改 DTO”
- 只更新允许修改的字段

## 6. 常见扩展

### 6.1 头像上传

头像字段本身只是一个 URL，真正实现常常要结合文件上传系统。

### 6.2 手机号修改

严格一点的系统里，手机号修改通常要二次验证码校验，不会直接允许修改。

### 6.3 邮箱修改

邮箱修改很多时候也会加激活确认流程。

## 7. 常见坑点

### 7.1 允许修改过多敏感字段

用户资料管理不应该让用户自己改角色、账号状态、系统标识。

### 7.2 不做唯一性校验

如果邮箱、手机号要求唯一，更新时也必须校验是否重复。

### 7.3 不做当前用户隔离

资料管理一定是“只能改自己”，不要让前端传任意用户 ID 来更新。

## 8. 总结

用户资料管理的核心，是围绕“当前登录用户”提供安全、边界清晰的资料查询和更新能力。

真正重要的不是代码多少，而是字段边界要控制好：哪些字段能改，哪些字段不能改，哪些字段需要额外校验。这些设计决定了资料管理是否真正可落地。
