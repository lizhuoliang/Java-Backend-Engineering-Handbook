# 菜单权限实现

## 1. 功能定义

菜单权限要解决的问题是：

- 当前用户登录后，左侧菜单应该看到哪些项
- 哪些目录可以展开
- 哪些页面路由可以访问

它和接口权限很像，但目标不同：

- 接口权限控制“能不能调用后端接口”
- 菜单权限控制“前端该展示什么导航结构”

在工程化项目里，菜单权限通常建立在 `RBAC` 之上，也就是：

1. 角色拥有菜单权限
2. 用户拥有角色
3. 登录后查询用户可见菜单树

## 2. 典型数据结构

菜单表通常至少要能表达层级关系、路由信息和权限标识。

```json
[
  {
    "id": 1,
    "parentId": 0,
    "menuName": "系统管理",
    "menuType": "MENU",
    "path": "/system",
    "component": "Layout",
    "permissionCode": ""
  },
  {
    "id": 2,
    "parentId": 1,
    "menuName": "用户管理",
    "menuType": "MENU",
    "path": "/system/user",
    "component": "system/user/index",
    "permissionCode": "user:list"
  }
]
```

角色和菜单通常还会有一张关系表：

```json
[
  {
    "roleId": 1,
    "menuId": 1
  },
  {
    "roleId": 1,
    "menuId": 2
  }
]
```

## 3. 核心设计

菜单权限实现最关键的点有 3 个：

1. 菜单本质上是一棵树
2. 用户拿到的不是平铺菜单，而是“当前用户可见的菜单树”
3. 父菜单即使本身不跳页面，也常常需要因为子菜单可见而一起返回

## 4. 典型流程

1. 用户登录
2. 根据用户角色查询可见菜单
3. 将平铺菜单组装成树
4. 返回前端
5. 前端动态渲染侧边栏和路由

## 5. 核心代码

## 5.1 菜单查询接口

```java
@RestController
@RequestMapping("/menu")
public class MenuController {

    private final MenuService menuService;

    public MenuController(MenuService menuService) {
        this.menuService = menuService;
    }

    @GetMapping("/my")
    public Result<List<MenuTreeVO>> myMenus() {
        Long userId = UserContext.get().getUserId();
        return Result.success(menuService.getCurrentUserMenuTree(userId));
    }
}
```

## 5.2 菜单树节点对象

这里只保留返回前端真正需要的字段。

```java
public class MenuTreeVO {

    private Long id;
    private String menuName;
    private String path;
    private String component;
    private List<MenuTreeVO> children = new ArrayList<>();

    public Long getId() {
        return id;
    }

    public void setId(Long id) {
        this.id = id;
    }

    public String getMenuName() {
        return menuName;
    }

    public void setMenuName(String menuName) {
        this.menuName = menuName;
    }

    public String getPath() {
        return path;
    }

    public void setPath(String path) {
        this.path = path;
    }

    public String getComponent() {
        return component;
    }

    public void setComponent(String component) {
        this.component = component;
    }

    public List<MenuTreeVO> getChildren() {
        return children;
    }
}
```

## 5.4 Service 核心实现

菜单权限的核心不是查库，而是“查出菜单后组装树”。

```java
@Service
public class MenuServiceImpl implements MenuService {

    private final MenuMapper menuMapper;

    public MenuServiceImpl(MenuMapper menuMapper) {
        this.menuMapper = menuMapper;
    }

    @Override
    public List<MenuTreeVO> getCurrentUserMenuTree(Long userId) {
        List<Menu> menuList = menuMapper.selectMenusByUserId(userId);
        if (menuList == null || menuList.isEmpty()) {
            return Collections.emptyList();
        }

        List<MenuTreeVO> nodeList = menuList.stream().map(menu -> {
            MenuTreeVO vo = new MenuTreeVO();
            vo.setId(menu.getId());
            vo.setMenuName(menu.getMenuName());
            vo.setPath(menu.getPath());
            vo.setComponent(menu.getComponent());
            return vo;
        }).toList();

        Map<Long, MenuTreeVO> nodeMap = nodeList.stream()
                .collect(Collectors.toMap(MenuTreeVO::getId, item -> item));

        List<MenuTreeVO> rootList = new ArrayList<>();
        for (Menu menu : menuList) {
            MenuTreeVO current = nodeMap.get(menu.getId());
            if (menu.getParentId() == 0) {
                rootList.add(current);
                continue;
            }
            MenuTreeVO parent = nodeMap.get(menu.getParentId());
            if (parent != null) {
                parent.getChildren().add(current);
            }
        }
        return rootList;
    }
}
```

### Mapper 核心思路

```java
public interface MenuMapper {

    List<Menu> selectMenusByUserId(Long userId);
}
```

这条查询的本质仍然是：

```text
用户 -> 角色 -> 角色菜单关系 -> 菜单
```

## 6. 返回前端的数据示例

```json
[
  {
    "id": 1,
    "menuName": "系统管理",
    "path": "/system",
    "component": "Layout",
    "children": [
      {
        "id": 2,
        "menuName": "用户管理",
        "path": "/system/user",
        "component": "system/user/index",
        "children": []
      }
    ]
  }
]
```

前端拿到这份数据后，就可以动态渲染导航菜单和路由。

## 7. 常见坑点

### 7.1 只返回叶子菜单，不返回父节点

这样前端虽然知道“用户管理”可见，但“系统管理”这个目录没法正常展示。

### 7.2 菜单树组装放前端做太多

后端最好直接返回结构化树，减少前端重复处理。

### 7.3 菜单权限和接口权限完全混在一起

它们可以复用同一个 `permissionCode`，但概念上仍然建议区分：

- 菜单控制展示
- 接口控制访问

## 8. 总结

菜单权限的核心不是“数据库里有菜单表”，而是基于用户角色查出当前用户可见菜单，并把平铺数据组装成树返回给前端。

它是 `RBAC` 在前端导航层面的直接落地，也是后台管理系统里最常见的一类权限能力。
