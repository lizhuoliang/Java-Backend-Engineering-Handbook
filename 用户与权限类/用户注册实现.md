# 用户注册实现

## 1. 功能定义

用户注册的目标，是让一个未登录的新用户通过提交必要信息创建系统账号，并完成后续可登录的前置准备。

在工程化项目里，注册功能看起来只是一次“插入用户表”，但真正落地时通常需要同时处理下面这些问题：

- 参数是否合法
- 用户名、手机号、邮箱是否重复
- 密码如何安全保存
- 是否需要验证码校验
- 是否要防止重复提交和恶意刷接口
- 注册成功后是否要初始化默认角色、默认资料、默认配置
- 注册失败时如何回滚

所以，一个完整的注册功能，本质上是一个“带校验、带安全、带并发保护、带业务初始化”的用户创建流程。

## 2. 适用技术栈

本文默认采用下面这套技术栈：

- `Spring Boot`
- `MyBatis-Plus`
- `MySQL`
- `Redis`

## 3. 一个可落地的注册流程

推荐把用户注册流程设计为下面这几个步骤：

1. 前端提交注册请求
2. 后端进行参数校验
3. 校验验证码或短信码
4. 检查用户名、手机号、邮箱是否已存在
5. 对密码进行加密
6. 创建用户主记录
7. 初始化默认角色或默认资料
8. 清理 Redis 中的验证码缓存
9. 返回注册成功结果

## 4. 注册功能的分层设计

一个典型后端项目里，注册功能一般放在下面这些层里：

### 4.1 Controller 层

负责接收前端请求，完成入参接收和基础校验，不写业务细节。

### 4.2 Service 层

负责注册核心业务流程，例如唯一性检查、密码加密、保存用户、初始化默认角色、清理验证码。

### 4.3 Mapper 层

负责和数据库交互。

### 4.4 Redis 层

负责验证码、注册防刷标记、短时幂等标记等缓存能力。

## 9.2 Redis 验证码服务

```java
package com.example.auth.service;

public interface VerifyCodeService {

    void validateRegisterCode(String phone, String code);

    void removeRegisterCode(String phone);
}
```

```java
package com.example.auth.service.impl;

import com.example.auth.service.VerifyCodeService;
import com.example.common.exception.BizException;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;

@Service
public class VerifyCodeServiceImpl implements VerifyCodeService {

    private static final String REGISTER_CODE_PREFIX = "register:code:";

    private final StringRedisTemplate stringRedisTemplate;

    public VerifyCodeServiceImpl(StringRedisTemplate stringRedisTemplate) {
        this.stringRedisTemplate = stringRedisTemplate;
    }

    @Override
    public void validateRegisterCode(String phone, String code) {
        String cacheCode = stringRedisTemplate.opsForValue().get(REGISTER_CODE_PREFIX + phone);
        if (cacheCode == null) {
            throw new BizException("验证码已过期");
        }
        if (!cacheCode.equals(code)) {
            throw new BizException("验证码错误");
        }
    }

    @Override
    public void removeRegisterCode(String phone) {
        stringRedisTemplate.delete(REGISTER_CODE_PREFIX + phone);
    }
}
```

## 9.3 Service 核心实现

```java
package com.example.auth.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.example.auth.dto.UserRegisterRequest;
import com.example.auth.entity.User;
import com.example.auth.mapper.UserMapper;
import com.example.auth.service.UserService;
import com.example.auth.service.VerifyCodeService;
import com.example.common.exception.BizException;
import java.time.LocalDateTime;
import org.springframework.dao.DuplicateKeyException;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.util.StringUtils;

@Service
public class UserServiceImpl implements UserService {

    private final UserMapper userMapper;
    private final VerifyCodeService verifyCodeService;
    private final PasswordEncoder passwordEncoder;

    public UserServiceImpl(
            UserMapper userMapper,
            VerifyCodeService verifyCodeService,
            PasswordEncoder passwordEncoder) {
        this.userMapper = userMapper;
        this.verifyCodeService = verifyCodeService;
        this.passwordEncoder = passwordEncoder;
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void register(UserRegisterRequest request) {
        validateBusinessRule(request);

        verifyCodeService.validateRegisterCode(request.getPhone(), request.getVerifyCode());

        checkUnique(request);

        User user = buildUser(request);

        try {
            userMapper.insert(user);
        } catch (DuplicateKeyException ex) {
            throw new BizException("用户名、手机号或邮箱已存在");
        }

        initDefaultUserData(user);

        verifyCodeService.removeRegisterCode(request.getPhone());
    }

    private void validateBusinessRule(UserRegisterRequest request) {
        if (!request.getPassword().equals(request.getConfirmPassword())) {
            throw new BizException("两次输入的密码不一致");
        }
    }

    private void checkUnique(UserRegisterRequest request) {
        Long usernameCount = userMapper.selectCount(
                new LambdaQueryWrapper<User>()
                        .eq(User::getUsername, request.getUsername()));
        if (usernameCount > 0) {
            throw new BizException("用户名已存在");
        }

        Long phoneCount = userMapper.selectCount(
                new LambdaQueryWrapper<User>()
                        .eq(User::getPhone, request.getPhone()));
        if (phoneCount > 0) {
            throw new BizException("手机号已注册");
        }

        if (StringUtils.hasText(request.getEmail())) {
            Long emailCount = userMapper.selectCount(
                    new LambdaQueryWrapper<User>()
                            .eq(User::getEmail, request.getEmail()));
            if (emailCount > 0) {
                throw new BizException("邮箱已注册");
            }
        }
    }

    private User buildUser(UserRegisterRequest request) {
        User user = new User();
        user.setUsername(request.getUsername());
        user.setPassword(passwordEncoder.encode(request.getPassword()));
        user.setNickname(request.getUsername());
        user.setPhone(request.getPhone());
        user.setEmail(request.getEmail());
        user.setStatus(1);
        user.setDeleted(0);
        user.setCreateTime(LocalDateTime.now());
        user.setUpdateTime(LocalDateTime.now());
        return user;
    }

    private void initDefaultUserData(User user) {
        // 这里可以扩展默认角色、默认头像、默认配置等初始化逻辑
    }
}
```

## 10. 密码加密配置

注册场景里，密码绝对不能明文入库。

推荐直接使用 `BCryptPasswordEncoder`。

```java
package com.example.auth.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;

@Configuration
public class PasswordConfig {

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
```

### 10.1 为什么不能自己写 MD5

- `MD5` 已经不安全
- 单次哈希很容易被撞库和暴力破解
- `BCrypt` 自带随机盐，且更适合密码存储

如果系统还在用“前端加密一次，后端再存库”的方式，也不能替代服务端密码加密。

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidException(MethodArgumentNotValidException ex) {
        String message = ex.getBindingResult().getFieldError() != null
                ? ex.getBindingResult().getFieldError().getDefaultMessage()
                : "参数校验失败";
        return Result.fail(message);
    }

    public Result<Void> handleConstraintViolationException(ConstraintViolationException ex) {
        return Result.fail(ex.getMessage());
    }

    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception ex) {
        return Result.fail("系统异常");
    }
}

## 13. 用户注册的完整时序

```java
/*
前端
  -> AuthController.register()
  -> UserService.register()
  -> 参数业务校验
  -> Redis 校验验证码
  -> 查询用户名/手机号/邮箱是否重复
  -> BCrypt 加密密码
  -> 插入用户表
  -> 初始化默认数据
  -> 删除 Redis 验证码
  -> 返回成功
*/
```

## 14. 为什么注册功能要这样设计

### 14.1 参数校验和业务校验分开

参数校验负责检查“格式对不对”，例如不能为空、长度是否合法、手机号格式是否合法。  
业务校验负责检查“业务上能不能注册”，例如密码是否一致、用户名是否重复、验证码是否正确。

这样职责更清晰，也更方便维护。

### 14.2 先查重，再入库，但最终仍依赖唯一索引

只做“先查数据库，再插入”是不够的。  
因为两个并发请求可能同时查到“不存在”，然后都去插入。

所以正确做法是：

- 代码层先做一次用户友好的提前校验
- 数据库层再用唯一索引兜底
- 插入时报唯一键异常时统一转成业务异常

### 14.3 使用事务

如果注册不仅仅是写用户表，还要写：

- 用户角色关系表
- 用户详情表
- 用户积分初始化表
- 用户欢迎消息表

那么这些步骤必须放在一个事务里，避免出现“用户表写成功了，但角色表没写成功”的脏数据。

## 15. Redis 在注册场景里的典型用途

在注册功能里，Redis 不只是放验证码，还常用于下面几个点：

### 15.1 短信验证码缓存

- key 可以设计为 `register:code:手机号`
- 设置 5 分钟过期

### 15.2 注册接口限流

例如一个 IP 在一分钟内最多注册尝试 5 次，防止恶意刷接口。

### 15.3 重复提交保护

前端短时间内重复点击“注册”，可以用 Redis 做一个短期请求标记。

## 16. 常见坑点

### 16.1 明文密码入库

这是最严重的问题之一。  
任何场景下都不能把密码明文存数据库。

### 16.2 只做业务查重，不做数据库唯一约束

这会在并发下产生重复数据。

### 16.3 把所有逻辑堆到 Controller

这样会导致代码难维护，后面加短信注册、邮箱注册、第三方注册时会非常痛苦。

### 16.4 验证码用完不删除

如果验证码使用后不清理，容易引发重复使用问题。

### 16.5 异常信息暴露过多

注册接口返回的信息要友好，但不要泄露系统内部实现细节。

## 17. 可扩展实现方向

注册功能在真实项目里通常会继续扩展成下面几种形式：

### 17.1 用户名密码注册

这是最基础的形式，适合后台管理系统、普通 Web 系统。

### 17.2 手机号验证码注册

移动端系统最常见，注册和登录往往都会走短信验证码。

### 17.3 邮箱注册

需要邮件验证码或激活链接。

### 17.4 第三方账号注册

例如微信、QQ、GitHub、Google 登录后自动注册本地账号。

### 17.5 邀请制注册

有的邀请码、渠道码、企业组织码等约束。

## 18. 面试里经常会问什么

### 18.1 用户注册你会怎么设计

回答重点：

- 参数校验
- 验证码校验
- 唯一性检查
- 密码加密
- 事务控制
- 唯一索引兜底
- 注册后初始化

### 18.2 为什么代码查重了，还要加数据库唯一索引

回答重点：

- 代码查重无法彻底解决并发问题
- 唯一索引是最终一致性约束

### 18.3 为什么密码要用 BCrypt

回答重点：

- 适合密码存储
- 带盐
- 抗暴力破解能力更强

### 18.4 Redis 在注册场景里怎么用

回答重点：

- 验证码缓存
- 防刷限流
- 重复提交保护

## 19. 一套比较完整的注册实现总结

如果把本文压缩成一句话，一个工程化的用户注册实现应该是：

前端提交注册请求后，后端通过 `Controller + Service + Mapper` 分层处理，先做参数校验和业务校验，再借助 Redis 校验验证码，借助 `BCrypt` 加密密码，借助 MyBatis-Plus 持久化用户数据，借助数据库唯一索引兜底并发重复问题，最后在事务中完成用户初始化与结果返回。

这才是一个比较接近真实项目的“用户注册实现”，而不只是简单地往用户表插一条数据。
