# 联想词实现

## 1. 功能定义

联想词要解决的问题是：

- 用户输入部分内容时，系统如何根据已有词库或搜索历史，自动补全可能的查询词

例如用户输入：

- `jav`

系统给出：

- `java`
- `java并发`
- `java集合`

它和搜索建议相近，但联想词通常更强调：

- 前缀补全
- 词级别匹配
- 输入过程中的即时反馈

## 2. 联想词的典型来源

联想词通常来自这些数据源：

1. 搜索热词
2. 真实业务标题抽取词
3. 用户历史搜索词
4. 运营预置词库

一个成熟的联想词系统，往往不是只从一个地方来，而是多来源融合。

## 3. 核心设计

联想词实现时，建议先明确：

1. 是按前缀补全，还是模糊联想
2. 数据来源是实时生成还是离线维护
3. 是否按热度排序
4. 是否需要去重
5. 是否要支持拼音、简写等扩展

对于大多数系统来说，第一阶段做“前缀补全 + 热度排序”已经很实用了。

## 4. 典型流程

1. 用户输入一段前缀
2. 系统从联想词库里查前缀命中的词
3. 按热度排序
4. 返回前 N 个补全结果

## 5. 常见实现方式

### 5.1 数据库前缀匹配

适合：

- 词库不大
- 需求简单

### 5.2 Redis 有序集合 / Trie 前缀树

适合：

- 高频调用
- 响应速度要求高

### 5.3 Elasticsearch completion suggester

适合：

- 检索系统已经基于 ES
- 希望建议词和全文检索体系打通

本文先从更容易理解的“Redis + 热词”思路切入。

## 6. 核心代码

## 6.1 联想词缓存结构示意

可以在 Redis 里维护：

```json
{
  "key": "search:hot_words",
  "value": [
    "java",
    "java并发",
    "java集合"
  ]
}
```

如果进一步优化，也可以做前缀索引缓存。

## 6.2 联想词核心实现

这里先用一个简单但很实用的思路：

- 把热词加载到内存或缓存
- 做前缀过滤

```java
@Service
public class SearchAssociateServiceImpl implements SearchAssociateService {

    private final StringRedisTemplate stringRedisTemplate;

    public SearchAssociateServiceImpl(StringRedisTemplate stringRedisTemplate) {
        this.stringRedisTemplate = stringRedisTemplate;
    }

    @Override
    public List<String> associate(String prefix) {
        if (!StringUtils.hasText(prefix)) {
            return Collections.emptyList();
        }

        List<String> hotWords = stringRedisTemplate.opsForList().range("search:hot_words", 0, 200);
        if (hotWords == null || hotWords.isEmpty()) {
            return Collections.emptyList();
        }

        return hotWords.stream()
                .filter(word -> word.startsWith(prefix))
                .limit(10)
                .toList();
    }
}
```

这段代码虽然很基础，但已经体现了联想词实现里的几个重点：

- 前缀匹配
- 热词池
- 返回数量限制

## 7. 为什么联想词通常不直接查业务大表

因为联想词接口往往是：

- 高频
- 短请求
- 实时触发

用户每多输入一个字，都可能触发一次请求。  
如果每次都去查复杂业务表，代价会非常高。

所以联想词更适合依赖：

- 专门的词库表
- Redis 热词缓存
- ES suggestion 能力

而不是直接扫主业务表。

## 8. 热词怎么来

联想词的热度通常可以来自：

1. 用户真实搜索次数统计
2. 运营手工维护
3. 内容标题定期抽取

很多正式系统会做一个离线任务，定期把：

- 最近高频搜索词

同步到建议词或联想词缓存里。

## 9. 搜索建议和联想词如何配合

可以这样理解：

- 联想词更偏输入补全
- 搜索建议更偏推荐候选

在简单系统里，这两个能力甚至可以共用同一个接口；  
在复杂系统里，则会拆成不同策略层。

## 10. 常见坑点

### 10.1 每次实时查大表

对高频输入场景非常不友好。

### 10.2 联想词不排序

用户看到的结果质量会很不稳定。

### 10.3 完全依赖静态词库

很容易和真实搜索趋势脱节。

## 11. 总结

联想词的核心，是为用户输入过程提供一层轻量、快速、可补全的词级提示能力。

它最重要的不是算法有多复杂，而是：

- 前缀匹配够快
- 热词来源合理
- 结果数量可控

一旦这三点做稳，它就能明显提升搜索输入体验。
