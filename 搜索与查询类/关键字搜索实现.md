# 关键字搜索实现

## 1. 功能定义

关键字搜索要解决的问题是：

- 用户输入一个词或一句短语后，系统如何快速从大量数据里找到相关结果

这是几乎所有后台系统和内容系统都会遇到的基础能力。  
常见场景包括：

- 按商品名搜索商品
- 按文章标题搜索文章
- 按用户名搜索用户
- 按订单号搜索订单

从工程角度看，关键字搜索看似只是一个输入框，但它背后其实包含了几个核心问题：

- 搜什么字段
- 是精确查还是模糊查
- 搜索速度是否能接受
- 数据量大了之后还扛不扛得住

所以关键字搜索本质上是“查询体验”和“数据检索能力”的第一层入口。

## 2. 关键字搜索和普通条件查询的区别

它们看起来很像，但侧重点不同。

- 普通条件查询更偏结构化字段过滤
- 关键字搜索更偏用户自然输入的检索体验

例如用户输入：

- `张三`
- `Java 并发`
- `ORD20260602`

这时候系统通常不是简单按一个字段等值匹配，而是希望：

- 在多个字段中查
- 做模糊匹配
- 尽可能把相关结果找出来

## 3. 常见实现方式

关键字搜索常见有两种落地方式。

### 3.1 数据库模糊搜索

例如：

- `like '%keyword%'`

适合：

- 数据量不大
- 搜索字段较少
- 系统处于早期阶段

优点：

- 实现简单
- 不需要额外中间件

缺点：

- 数据量一大性能会明显下降
- 查询体验一般

### 3.2 搜索引擎搜索

例如：

- `Elasticsearch`

适合：

- 内容多
- 检索要求高
- 需要分词、相关度排序、高亮

本文先讲“数据库关键字搜索”的典型实现，再说明它什么时候该升级成全文搜索。

## 4. 典型流程

一个基础关键字搜索流程通常如下：

1. 用户输入关键字
2. 后端接收关键字和分页参数
3. 对关键字做空值和长度校验
4. 在指定字段上做模糊查询
5. 返回分页结果

## 5. 核心设计

关键字搜索实现时，建议至少明确：

1. 搜索哪些字段
2. 空关键字时返回什么
3. 是否允许跨字段搜索
4. 是否需要分页
5. 是否要限制关键字长度

其中第 5 点很容易被忽略。  
如果用户一次性传超长搜索词，不但体验差，还可能给数据库带来不必要的压力。

## 6. 典型请求

```json
{
  "keyword": "Java",
  "pageNum": 1,
  "pageSize": 10
}
```

## 7. 核心代码

## 7.1 搜索请求对象

```java
public class KeywordSearchRequest extends PageRequest {

    private String keyword;

    public String getKeyword() {
        return keyword;
    }

    public void setKeyword(String keyword) {
        this.keyword = keyword;
    }
}
```

## 7.2 关键字搜索核心实现

这里用“文章搜索”举例，搜索标题和摘要两个字段。

```java
@Service
public class ArticleSearchServiceImpl implements ArticleSearchService {

    private final ArticleMapper articleMapper;

    public ArticleSearchServiceImpl(ArticleMapper articleMapper) {
        this.articleMapper = articleMapper;
    }

    @Override
    public PageResult<ArticleVO> search(KeywordSearchRequest request) {
        String keyword = request.getKeyword();
        if (!StringUtils.hasText(keyword)) {
            throw new BizException("搜索关键字不能为空");
        }
        if (keyword.length() > 50) {
            throw new BizException("搜索关键字过长");
        }

        Page<Article> page = new Page<>(request.getPageNum(), Math.min(request.getPageSize(), 50L));

        LambdaQueryWrapper<Article> wrapper = new LambdaQueryWrapper<Article>()
                .and(w -> w.like(Article::getTitle, keyword)
                        .or()
                        .like(Article::getSummary, keyword))
                .eq(Article::getStatus, 1)
                .orderByDesc(Article::getCreateTime);

        Page<Article> resultPage = articleMapper.selectPage(page, wrapper);

        List<ArticleVO> list = resultPage.getRecords().stream().map(item -> {
            ArticleVO vo = new ArticleVO();
            vo.setId(item.getId());
            vo.setTitle(item.getTitle());
            vo.setSummary(item.getSummary());
            return vo;
        }).toList();

        return new PageResult<>(list, resultPage.getTotal(), request.getPageNum(), request.getPageSize());
    }
}
```

这段代码里最重要的几个点是：

- 搜索关键字不能为空
- 关键字长度有限制
- 支持在多个字段上做模糊匹配
- 搜索结果依然走分页

## 8. 为什么关键字搜索通常要限制搜索字段

很多初学者会想：

- 既然要搜索，那就把所有字段都拿来搜

但工程上这样做通常很差。  
因为：

1. 会让 SQL 很重
2. 会降低结果相关性
3. 很多字段其实没有搜索意义

例如文章系统里更适合搜索：

- 标题
- 摘要

而不是：

- 创建人 ID
- 状态枚举字段

所以关键字搜索字段一定要有明确边界。

## 9. 为什么数据库关键字搜索会越来越吃力

因为数据库模糊搜索通常依赖：

- `like '%xxx%'`

这种查询方式在数据量小时还能接受，但一旦：

- 数据量上百万
- 搜索字段变多
- 用户并发上来

性能会明显恶化。

这也是为什么很多系统一开始用数据库关键字搜索，后面会逐步演进到：

- 全文检索
- Elasticsearch

## 10. 常见优化思路

在还没上搜索引擎之前，关键字搜索常见的优化方式包括：

1. 限制搜索字段数量
2. 限制分页大小
3. 优先搜索前缀匹配场景
4. 对常用查询字段建立索引
5. 搜索和普通列表接口拆开

不过要注意：

- 普通索引对 `%keyword%` 模式帮助有限

所以优化空间是有限的，不能把数据库模糊搜索当成万能方案。

## 11. 常见坑点

### 11.1 搜索字段无限扩张

很容易把查询性能拖垮。

### 11.2 不做分页

关键字搜索往往是高频入口，不分页风险很大。

### 11.3 关键字为空时直接全表模糊查

这会造成非常不必要的数据库压力。

### 11.4 所有搜索都硬扛在数据库上

数据量一大后，体验和性能都会明显变差。

## 12. 总结

关键字搜索的核心，不是“写一个 like”，而是为用户提供一个有边界、可分页、可承载一定数据量的文本检索入口。

在系统早期阶段，数据库模糊搜索完全可以作为起点；但只要你把搜索体验和性能当成长期能力去建设，就必须从一开始明确：

- 搜什么
- 怎么搜
- 什么时候该升级到全文检索

这才是关键字搜索真正有工程价值的地方。
