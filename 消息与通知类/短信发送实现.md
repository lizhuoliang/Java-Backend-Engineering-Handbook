# 短信发送实现

## 1. 功能定义

短信发送要解决的问题是：

- 把系统中的通知或验证码，通过手机短信渠道送达到用户

常见场景包括：

- 登录验证码
- 注册验证码
- 密码找回验证码
- 支付成功通知
- 风险告警通知

和站内信不同，短信发送本质上依赖第三方通道能力，所以它不仅是一个代码问题，还是一个“系统对接外部服务”的问题。

## 2. 短信发送的特点

短信有几个很鲜明的工程特征：

1. 强触达  
只要手机号有效，触达率通常较高。

2. 有成本  
每发一条短信通常都要付费。

3. 依赖第三方平台  
例如阿里云短信、腾讯云短信等。

4. 风险高  
如果不做限流和防刷，很容易被恶意消耗资源。

所以短信发送绝不能只写成一个“调用 SDK 的方法”。

## 3. 典型流程

一个比较完整的短信发送流程通常如下：

1. 前端提交手机号
2. 后端校验手机号格式
3. 生成验证码或通知内容
4. 做发送频率限制
5. 调用短信平台发送
6. 把验证码缓存到 Redis
7. 记录发送日志

如果是通知型短信，则第 6 步可能不需要验证码缓存，但仍然建议记录发送日志。

## 4. 核心设计

短信系统设计时，最少要考虑这几个点：

1. 短信内容尽量模板化
2. 发送频率必须限制
3. 验证码要设置有效期
4. 发送日志要落库，便于追踪失败
5. 通道调用尽量抽象成统一接口

## 6. 核心代码

## 6.1 短信发送统一接口

```java
public interface SmsSender {

    void send(String phone, String templateCode, Map<String, String> params);
}
```

这个接口很关键，因为后续你换短信平台时，上层业务不应该跟着大改。

## 6.2 验证码发送核心实现

```java
@Service
public class SmsCodeServiceImpl implements SmsCodeService {

    private static final String CODE_KEY_PREFIX = "sms:code:login:";
    private static final String LIMIT_KEY_PREFIX = "sms:limit:";

    private final SmsSender smsSender;
    private final StringRedisTemplate stringRedisTemplate;
    private final SmsLogMapper smsLogMapper;

    public SmsCodeServiceImpl(
            SmsSender smsSender,
            StringRedisTemplate stringRedisTemplate,
            SmsLogMapper smsLogMapper) {
        this.smsSender = smsSender;
        this.stringRedisTemplate = stringRedisTemplate;
        this.smsLogMapper = smsLogMapper;
    }

    @Override
    public void sendLoginCode(String phone) {
        if (!phone.matches("^1[3-9]\\d{9}$")) {
            throw new BizException("手机号格式不正确");
        }

        String limitKey = LIMIT_KEY_PREFIX + phone;
        Boolean first = stringRedisTemplate.opsForValue().setIfAbsent(limitKey, "1", Duration.ofSeconds(60));
        if (Boolean.FALSE.equals(first)) {
            throw new BizException("发送过于频繁，请稍后再试");
        }

        String code = String.valueOf(ThreadLocalRandom.current().nextInt(1000, 10000));

        try {
            smsSender.send(phone, "login_code", Map.of("code", code));
            stringRedisTemplate.opsForValue().set(CODE_KEY_PREFIX + phone, code, Duration.ofMinutes(5));

            SmsLog log = new SmsLog();
            log.setPhone(phone);
            log.setTemplateCode("login_code");
            log.setContent("code=" + code);
            log.setStatus("SUCCESS");
            log.setSendTime(LocalDateTime.now());
            smsLogMapper.insert(log);
        } catch (Exception ex) {
            SmsLog log = new SmsLog();
            log.setPhone(phone);
            log.setTemplateCode("login_code");
            log.setStatus("FAIL");
            log.setFailReason(ex.getMessage());
            log.setSendTime(LocalDateTime.now());
            smsLogMapper.insert(log);
            throw new BizException("短信发送失败");
        }
    }
}
```

这段代码里真正重要的不是“生成了 4 位验证码”，而是：

- 做了频率限制
- 调用了统一发送接口
- 成功后写 Redis
- 不管成功失败都记录日志

## 7. 为什么短信发送一定要限流

因为短信是有成本的，而且很容易被刷。

如果不限制，一个攻击者可以：

- 不断请求验证码
- 消耗你的短信额度
- 干扰正常用户接收短信

工程里至少通常会做两层限制：

1. 单手机号一分钟只能发一次
2. 单 IP 或单设备一天有总量限制

## 8. 短信验证码和通知短信的区别

虽然都叫“短信发送”，但这两类场景其实不完全一样。

### 验证码短信

特点：

- 实时性强
- 内容短
- 有效期短
- 需要 Redis 缓存验证码

### 通知短信

特点：

- 更偏业务事件通知
- 一般不需要验证码缓存
- 更关注发送成功率和补发策略

所以在工程实现里，最好不要把所有短信场景都硬塞进一个方法里。

## 9. 常见坑点

### 9.1 短信发送不做频率控制

这是最典型的问题之一。

### 9.2 验证码发出去了但不落 Redis

后续校验时就无从验证。

### 9.3 调用第三方失败后没有日志

排查问题会非常困难。

### 9.4 业务代码直接依赖某个短信平台 SDK

后期换通道时成本会很高。

## 10. 总结

短信发送的工程重点，不在“会不会调用短信 SDK”，而在于通道抽象、频率控制、验证码缓存、发送日志和失败追踪。

如果只用一句话概括，一个成熟的短信发送实现至少应该做到：

- 平台调用可替换
- 验证码可缓存
- 请求可限流
- 结果可追踪

这才是真正能上线的短信系统骨架。
