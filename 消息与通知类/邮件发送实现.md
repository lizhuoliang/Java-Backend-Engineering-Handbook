# 邮件发送实现

## 1. 功能定义

邮件发送要解决的问题是：

- 把系统中的通知、验证码、报表或正式内容，通过邮件方式发送给用户

常见场景包括：

- 注册激活邮件
- 找回密码邮件
- 报表邮件
- 审批通知邮件
- 系统告警邮件

邮件和短信相比，通常更适合：

- 内容更长
- 格式更正式
- 带附件
- 需要保留痕迹

## 2. 邮件发送的工程特点

邮件发送通常有这些特点：

1. 内容形式更丰富  
可以发纯文本，也可以发 HTML。

2. 可带附件
3. 依赖邮件服务器或第三方服务
4. 对格式要求更高  
例如主题、发件人、模板内容。

所以邮件系统往往比短信系统更强调模板化和异步发送。

## 3. 典型流程

一个完整的邮件发送流程通常如下：

1. 业务发起邮件通知请求
2. 系统组装主题和内容
3. 如果有模板，就先渲染模板
4. 调用邮件发送组件
5. 记录发送日志
6. 失败时支持重试

## 4. 核心设计

邮件发送设计时，我建议重点考虑：

1. 邮件发送组件要统一封装
2. 支持纯文本和 HTML 邮件
3. 复杂邮件最好走模板引擎
4. 发送动作尽量异步
5. 落发送日志，便于追踪

## 5. 核心代码

## 5.1 邮件发送请求对象

```java
public class MailSendRequest {

    private String to;
    private String subject;
    private String content;
    private boolean html;

    public String getTo() {
        return to;
    }

    public void setTo(String to) {
        this.to = to;
    }

    public String getSubject() {
        return subject;
    }

    public void setSubject(String subject) {
        this.subject = subject;
    }

    public String getContent() {
        return content;
    }

    public void setContent(String content) {
        this.content = content;
    }

    public boolean isHtml() {
        return html;
    }

    public void setHtml(boolean html) {
        this.html = html;
    }
}
```

## 5.2 邮件发送核心实现

```java
@Service
public class MailServiceImpl implements MailService {

    private final JavaMailSender javaMailSender;
    private final MailLogMapper mailLogMapper;

    @Value("${spring.mail.username}")
    private String from;

    public MailServiceImpl(JavaMailSender javaMailSender, MailLogMapper mailLogMapper) {
        this.javaMailSender = javaMailSender;
        this.mailLogMapper = mailLogMapper;
    }

    @Override
    public void send(MailSendRequest request) {
        try {
            MimeMessage mimeMessage = javaMailSender.createMimeMessage();
            MimeMessageHelper helper = new MimeMessageHelper(mimeMessage, true, StandardCharsets.UTF_8.name());
            helper.setFrom(from);
            helper.setTo(request.getTo());
            helper.setSubject(request.getSubject());
            helper.setText(request.getContent(), request.isHtml());

            javaMailSender.send(mimeMessage);

            MailLog log = new MailLog();
            log.setToEmail(request.getTo());
            log.setSubject(request.getSubject());
            log.setStatus("SUCCESS");
            log.setSendTime(LocalDateTime.now());
            mailLogMapper.insert(log);
        } catch (Exception ex) {
            MailLog log = new MailLog();
            log.setToEmail(request.getTo());
            log.setSubject(request.getSubject());
            log.setStatus("FAIL");
            log.setFailReason(ex.getMessage());
            log.setSendTime(LocalDateTime.now());
            mailLogMapper.insert(log);
            throw new BizException("邮件发送失败");
        }
    }
}
```

这段代码里值得注意的点有两个：

- 支持 HTML 邮件
- 不论成功失败都落日志

## 6. 为什么邮件更适合模板化

因为很多邮件内容都有固定骨架，例如：

- 标题栏
- 品牌头图
- 正文模块
- 底部版权信息

如果每次都手写 HTML，会非常难维护。  
所以工程里很常见的做法是：

1. 维护邮件模板
2. 传入参数渲染
3. 生成最终 HTML 内容

例如：

```json
{
  "templateCode": "register_active",
  "params": {
    "userName": "张三",
    "activeUrl": "https://example.com/active?token=abc"
  }
}
```

## 7. 附件邮件怎么理解

很多报表邮件、对账邮件会带附件。  
这时通常会扩展为：

- 正文内容
- 附件列表

代码上一般会在 `MimeMessageHelper` 上继续调用：

```java
helper.addAttachment("report.xlsx", file);
```

所以如果邮件系统一开始就考虑附件扩展，后期会更从容。

## 8. 为什么邮件发送通常适合异步

因为邮件发送本身依赖外部服务，速度并不稳定。  
如果在主业务线程里同步发送，可能带来：

- 接口响应慢
- 第三方波动拖累主流程

所以正式项目里，邮件发送通常会结合消息队列或异步任务执行。

## 9. 常见坑点

### 9.1 业务流程里直接同步发邮件

容易拖慢主流程。

### 9.2 不记录发送日志

失败时很难排查。

### 9.3 把 HTML 模板直接写死在 Java 代码里

后期改文案和样式都很痛苦。

## 10. 总结

邮件发送的核心，不是“能不能发出去”，而是建立一套可模板化、可追踪、可异步、可扩展附件的通知能力。

它和短信相比更适合正式通知和长内容，在很多企业系统里都是通知体系的重要组成部分。
