# 高并发与稳定性类

## 本类定位

这一类主要解决系统在“流量大、并发高、依赖多、故障复杂”时，怎么不崩、怎么扛住、怎么优雅失败。

它的核心问题不是“功能能不能做”，而是：

- 功能在压力下还能不能稳定做

这也是很多系统从“开发可用”走向“生产可用”的关键分水岭。

## 适用场景

- 热点接口治理
- 并发写保护
- 服务稳定性设计
- 高并发活动与秒杀场景
- 微服务故障隔离与恢复

## 推荐阅读顺序

推荐顺序如下：

1. 缓存 Redis
2. 接口幂等
3. 防重复提交
4. 限流
5. 防刷
6. 分布式锁
7. 异步削峰
8. 热点数据处理
9. 熔断
10. 降级
11. 隔离
12. 分库分表

这条顺序本质上是：

- 先学最常见的高并发基础件
- 再学稳定性保护链
- 最后再进入更重的容量扩展问题

## 与其他大类的关联

- 和 [业务流程类](../业务流程类/README.md) 的关系
订单、库存、支付、活动这些核心流程在高并发下最容易暴露稳定性问题。

- 和 [任务与调度类](../任务与调度类/README.md) 的关系
异步任务、重试、补偿、批处理都会和限流、隔离、削峰策略一起配合。

- 和 [运维与治理类](../运维与治理类/README.md) 的关系
熔断、降级、隔离等机制最终都需要监控、告警和日志来观察效果。
