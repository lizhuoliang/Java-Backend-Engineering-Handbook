# 图片管理实现

## 1. 功能定义

图片管理要解决的问题是：

- 系统里的图片如何上传、存储、展示、替换和删除

它和普通文件管理很像，但又有自己的特殊点：

- 更关注图片类型和尺寸
- 更关注访问展示
- 更容易涉及缩略图、水印、压缩

例如：

- 用户头像
- 商品主图
- 文章封面
- 富文本插图
- 轮播图

这些都属于图片管理能力。

## 2. 图片管理和普通文件管理的区别

从工程视角看，图片管理比普通文件管理多关心几件事：

1. 文件类型更明确  
通常只允许 `jpg/png/webp/jpeg` 等图片格式。

2. 访问频率更高  
图片经常直接用于页面展示，不只是下载。

3. 可能有衍生处理  
例如压缩、裁剪、缩略图、水印。

所以很多系统里，“图片管理”虽然底层仍然复用文件上传，但会单独抽业务能力。

## 3. 典型数据结构

```json
{
  "id": 2001,
  "originName": "cover.png",
  "storagePath": "https://cdn.example.com/image/20260601/cover-uuid.png",
  "width": 800,
  "height": 600,
  "size": 102400,
  "bizType": "article_cover"
}
```

相比普通文件，图片元数据里往往会额外关心：

- 宽度
- 高度
- 缩略图地址

## 4. 典型流程

1. 前端上传图片文件
2. 后端校验格式和大小
3. 读取图片基本信息
4. 存储原图
5. 如有需要，生成缩略图
6. 保存图片元数据
7. 返回访问 URL

## 5. 核心设计

图片管理设计时，我建议先明确这几点：

1. 图片上传接口要比普通文件限制更严格
2. 图片和附件可以复用底层文件表，但业务类型要区分
3. 展示用 URL 和管理用 fileId 最好同时保留
4. 如果会做压缩、裁剪、缩略图，尽量放在统一处理层

## 6. 核心代码

## 6.1 图片上传核心实现

```java
@Service
public class ImageServiceImpl implements ImageService {

    private static final long MAX_IMAGE_SIZE = 5 * 1024 * 1024L;
    private static final Set<String> ALLOW_SUFFIX = Set.of("jpg", "jpeg", "png", "webp");

    private final FileRecordMapper fileRecordMapper;

    @Override
    public ImageUploadVO uploadImage(MultipartFile file, String bizType) {
        if (file == null || file.isEmpty()) {
            throw new BizException("图片不能为空");
        }

        if (file.getSize() > MAX_IMAGE_SIZE) {
            throw new BizException("图片大小超过限制");
        }

        String suffix = getSuffix(file.getOriginalFilename());
        if (!ALLOW_SUFFIX.contains(suffix.toLowerCase())) {
            throw new BizException("图片格式不支持");
        }

        BufferedImage image;
        try {
            image = ImageIO.read(file.getInputStream());
        } catch (IOException ex) {
            throw new BizException("图片读取失败");
        }

        if (image == null) {
            throw new BizException("文件不是合法图片");
        }

        FileUploadVO uploadVO = fileStorageService.upload(file, bizType);

        ImageUploadVO vo = new ImageUploadVO();
        vo.setFileId(uploadVO.getFileId());
        vo.setUrl(uploadVO.getUrl());
        vo.setWidth(image.getWidth());
        vo.setHeight(image.getHeight());
        return vo;
    }

    private String getSuffix(String fileName) {
        if (!StringUtils.hasText(fileName) || !fileName.contains(".")) {
            throw new BizException("文件名不合法");
        }
        return fileName.substring(fileName.lastIndexOf('.') + 1);
    }
}
```

这一段和普通文件上传相比，多做了一个关键动作：

- 读取图片流，确认它真的是图片，并拿到宽高

## 7. 为什么图片不能只看后缀

因为：

- `xxx.png`

这个文件名并不能保证内容真的是 PNG 图片。

更稳的做法至少包括：

1. 校验后缀
2. 校验 `contentType`
3. 尝试读取图片内容

只要 `ImageIO.read()` 读不出来，就说明它并不是一张合法图片。

## 8. 图片展示和附件下载为什么是两套思维

图片一般更偏“在线访问和展示”，例如：

- `<img src="...">`
- 背景图
- 封面图

而附件更偏“下载和归档”，例如：

- 合同 PDF
- 压缩包
- 文档

所以图片管理常常更关心：

- URL 是否可公开访问
- 是否要经过 CDN
- 是否需要缩略图

## 9. 常见扩展

### 9.1 头像裁剪

很多系统里头像并不是直接上传原图，而是前端裁剪后再上传。

### 9.2 缩略图生成

商品图、相册图、文章封面图，经常会生成缩略图用于列表页展示。

### 9.3 水印处理

某些内容平台会给图片打水印。

## 10. 常见坑点

### 10.1 只校验后缀不校验内容

容易被伪装文件绕过。

### 10.2 原图直接全量展示

高分辨率大图直接在列表页使用，会拖慢页面加载。

### 10.3 图片和附件完全混在一个业务规则里

底层可复用，但上层最好区分能力边界。

## 11. 总结

图片管理虽然底层仍然建立在文件上传之上，但它更强调图片合法性、图片展示和图片衍生处理。一个工程化的图片管理实现，关键不是上传成功，而是让图片在“可校验、可展示、可扩展处理”这三件事上站得住。
