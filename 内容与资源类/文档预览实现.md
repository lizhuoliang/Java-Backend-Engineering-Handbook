# 文档预览实现

## 1. 功能定义

文档预览要解决的问题是：

- 用户不下载文件，也能在线查看内容

最常见的预览文件包括：

- `PDF`
- `Word`
- `Excel`
- 图片

在很多系统里，预览体验甚至比下载更重要，因为用户只是想“先看一眼”，并不一定要把文件保存到本地。

## 2. 常见预览方案

文档预览通常有 3 类方案。

### 2.1 浏览器原生可预览格式

例如：

- `PDF`
- 图片
- 部分文本文件

这种最简单，核心是返回一个浏览器可直接访问的 URL。

### 2.2 后端转换后预览

例如：

- Word 转 PDF
- Excel 转 PDF 或图片

适合需要统一预览体验的系统。

### 2.3 第三方在线预览服务

例如对接外部文档预览能力。  
适合快速接入，但会依赖外部服务。

## 3. 工程上最常见的思路

正式项目里比较常见的一条路线是：

1. 图片和 PDF 直接预览
2. Office 文档先转换成 PDF
3. 前端统一用 PDF 预览组件展示

因为：

- PDF 跨平台预览体验更稳定
- 浏览器兼容性也更好

## 4. 典型流程

1. 用户请求预览某个文件
2. 后端查询文件元数据
3. 判断文件类型
4. 如果本身可直接预览，就返回预览 URL
5. 如果不可直接预览，就尝试转换成 PDF 或图片
6. 返回预览地址

## 5. 核心代码

## 5.1 预览接口

```java
@RestController
@RequestMapping("/file")
public class FilePreviewController {

    private final FilePreviewService filePreviewService;

    public FilePreviewController(FilePreviewService filePreviewService) {
        this.filePreviewService = filePreviewService;
    }

    @GetMapping("/preview/{fileId}")
    public Result<FilePreviewVO> preview(@PathVariable Long fileId) {
        return Result.success(filePreviewService.preview(fileId));
    }
}
```

## 5.2 预览核心实现

```java
@Service
public class FilePreviewServiceImpl implements FilePreviewService {

    private static final Set<String> DIRECT_PREVIEW_SUFFIX = Set.of("pdf", "png", "jpg", "jpeg", "webp");

    private final FileRecordMapper fileRecordMapper;
    private final DocumentConvertService documentConvertService;

    public FilePreviewServiceImpl(
            FileRecordMapper fileRecordMapper,
            DocumentConvertService documentConvertService) {
        this.fileRecordMapper = fileRecordMapper;
        this.documentConvertService = documentConvertService;
    }

    @Override
    public FilePreviewVO preview(Long fileId) {
        FileRecord record = fileRecordMapper.selectById(fileId);
        if (record == null) {
            throw new BizException("文件不存在");
        }

        String suffix = getSuffix(record.getOriginName());
        if (DIRECT_PREVIEW_SUFFIX.contains(suffix.toLowerCase())) {
            return new FilePreviewVO("direct", record.getStoragePath());
        }

        String previewUrl = documentConvertService.convertToPreviewUrl(record);
        return new FilePreviewVO("converted", previewUrl);
    }

    private String getSuffix(String fileName) {
        if (!StringUtils.hasText(fileName) || !fileName.contains(".")) {
            return "";
        }
        return fileName.substring(fileName.lastIndexOf('.') + 1);
    }
}
```

这段代码表达的核心思想很简单：

- 能直接预览的，直接返回
- 不能直接预览的，走转换服务

## 6. 为什么很多系统喜欢“统一转 PDF”

因为直接预览 `Word/Excel/PPT` 的兼容性、前端处理成本和跨平台体验都不稳定。  
而统一转 PDF 后，前端展示会容易很多。

所以很多系统的文档预览本质上不是：

- 直接预览 Word

而是：

- 先把 Word 转成 PDF，再预览 PDF

## 7. 转换服务怎么理解

`DocumentConvertService` 的职责通常是：

1. 接收原始文档
2. 调用本地工具或第三方服务进行转换
3. 生成预览产物
4. 返回预览 URL

它内部可以是：

- LibreOffice 转 PDF
- 远程文档转换服务
- 商业文档预览服务

所以“文档预览”本身往往不是一个纯 Web 接口问题，而是一个带资源处理能力的系统设计问题。

## 8. 常见坑点

### 8.1 把下载地址当预览地址直接给前端

有些文件浏览器无法原生展示，体验会很差。

### 8.2 转换结果不缓存

同一个文件每次预览都重新转，会浪费很多资源。

### 8.3 忽略权限控制

预览虽然不是下载，但本质上也在访问文件内容，权限控制仍然要做。

## 9. 总结

文档预览的核心，不是“给前端一个链接”这么简单，而是根据文件类型决定采用哪种预览策略：

- 图片、PDF 直接预览
- Office 文档优先转 PDF
- 预览结果最好缓存复用

这样才能形成真正可用的文档预览能力。
