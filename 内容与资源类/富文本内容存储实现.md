# 富文本内容存储实现

## 1. 功能定义

富文本内容存储要解决的问题是：

- 用户在编辑器里输入的图文内容，如何安全、完整地保存下来

常见场景包括：

- 文章正文
- 公告内容
- 帮助中心
- 商品详情

富文本和普通文本最大的区别是：

- 它不仅有文字，还有 HTML 结构、图片、链接、样式信息

## 2. 常见存储方式

富文本内容常见有两种存储思路。

### 2.1 存 HTML

最常见，也最直接。  
前端编辑器输出什么，后端就保存什么。

优点：

- 简单
- 展示方便

缺点：

- 需要处理 XSS 风险
- 内容结构相对不受控

### 2.2 存 JSON 结构

某些编辑器会输出结构化 JSON，例如块级编辑器。

优点：

- 更利于二次处理
- 可扩展性强

缺点：

- 展示时通常还要额外渲染

对大多数 Java 后台项目来说，最常见的仍然是“存 HTML 内容”。

## 3. 典型数据示例

```json
{
  "title": "系统升级公告",
  "content": "<p>今晚进行系统升级</p><p><img src=\"https://cdn.example.com/a.png\" /></p>"
}
```

## 4. 核心设计

富文本内容存储时，最重要的不是“字段类型够不够大”，而是下面这些问题：

1. 内容字段是否足够存储长文本
2. 是否需要做 XSS 过滤
3. 内容里的图片如何管理
4. 展示时是否原样渲染

## 5. 富文本和文件上传的关系

富文本里最容易被忽略的一点是“内嵌图片”。

常见处理方式是：

1. 编辑器上传图片
2. 图片走统一文件上传接口
3. 上传成功后返回图片 URL
4. 编辑器把 URL 插入 HTML 内容
5. 最终 HTML 连同图片地址一起保存

也就是说：

- 富文本正文存的是 HTML
- 图片本身仍然走统一文件系统

## 6. 核心代码

## 6.1 内容保存接口

```java
@RestController
@RequestMapping("/article")
public class ArticleController {

    private final ArticleService articleService;

    public ArticleController(ArticleService articleService) {
        this.articleService = articleService;
    }

    @PostMapping
    public Result<Void> add(@RequestBody @Valid ArticleAddRequest request) {
        articleService.add(request);
        return Result.success();
    }
}
```

## 6.2 内容保存核心实现

```java
@Service
public class ArticleServiceImpl implements ArticleService {

    private final ArticleMapper articleMapper;

    public ArticleServiceImpl(ArticleMapper articleMapper) {
        this.articleMapper = articleMapper;
    }

    @Override
    public void add(ArticleAddRequest request) {
        String safeContent = Jsoup.clean(
                request.getContent(),
                Safelist.relaxed().addAttributes("img", "src", "alt", "width", "height")
        );

        Article article = new Article();
        article.setTitle(request.getTitle());
        article.setContent(safeContent);
        articleMapper.insert(article);
    }
}
```

这段代码最关键的地方不是插库，而是：

- 在保存前对 HTML 做了安全清洗

## 7. 为什么富文本内容要做 XSS 处理

因为富文本本质上可能包含 HTML 标签。  
如果直接无过滤保存和渲染，就可能把恶意脚本一起带进去。

例如攻击者可能构造：

```html
<script>alert('xss')</script>
```

所以富文本内容在保存或展示前，至少要有一层安全处理。  
很多 Java 项目里会用 `Jsoup` 做白名单清洗。

## 8. 内容字段在数据库里怎么设计

富文本内容通常比较长，所以数据库字段一般不会用普通 `varchar(255)`。  
更常见的是：

- `text`
- `mediumtext`
- `longtext`

具体选哪种，取决于你的内容体积。

## 9. 富文本图片如何治理

真实项目里，富文本图片管理是一个很容易被低估的问题。

例如：

- 文章草稿上传了图片，但没发布
- 正文里删掉了某张图片，但文件系统里还留着
- 内容修改后，有些旧图片已经不再被引用

如果系统规模大，后续通常会继续做：

1. 富文本图片引用分析
2. 无主图片清理
3. 图片资源生命周期管理

## 10. 常见坑点

### 10.1 直接原样存 HTML，不做安全处理

容易引发 XSS 问题。

### 10.2 富文本图片不走统一上传体系

后续内容迁移和资源治理都会很麻烦。

### 10.3 用普通短字符串字段存正文

内容一长就会被截断。

## 11. 总结

富文本内容存储的核心，不只是“存一段字符串”，而是围绕 HTML 内容、安全过滤和内嵌资源管理建立一套可长期维护的内容能力。

如果把它压缩成一句话，就是：

- 正文存富文本内容
- 图片走统一文件上传
- 内容保存前做安全清洗

这才是一套更像正式项目的实现方式。
